# 防漂移执行协议

本协议解决“不同模型昨天跑了一部分、今天另一个模型又按旧文档判断”的问题。它适用于 Codex、DeepSeek Harness、Hermes 或任何后续 Agent；不是要求反复切换模型。

## 一条任务，一份证据，一次合并

每次执行只领取一个 `DL-R4-xxx` 任务。开始时记录：base SHA、任务 ID、环境、输入 hash、预期产物。结束时只写一个 `task-result.json`，其中包含：实际 SHA、变更文件、命令、退出码、产物 hash、实机版本、剩余限制和回退步骤。

任务状态只能由 `task-result.json` 的验证脚本投影，禁止手工同时编辑多个“当前进度”文件。状态枚举固定：`NOT_STARTED`、`IMPLEMENTED`、`UNIT_VERIFIED`、`HOST_VERIFIED`、`BLOCKED`、`SUPERSEDED`。前端/宿主类任务没有真实软件读回时最多 `UNIT_VERIFIED`。

## 单一权威链

```
Task graph → task-result.json → verifier → current-status.json → README / report
```

- `tasks.json` 是唯一待办、依赖和验收来源。
- `task-result.json` 是一次执行的不可变事实记录；新尝试另建 attempt，不覆盖旧记录。
- `current-status.json` 是生成物，禁止手改。
- 历史台账保留原文并标 `historical`；不得作为当前任务启动指令。

## 多模型不互相打架

1. 一个任务同一时刻只允许一个执行器持有写租约；其他模型可审查、设计测试或做只读研究，不能同时改同一任务。
2. 执行器不需要切换模型才可完成任务：同一模型从实现、测试到提交连续完成。只有遇到明确能力边界时交接，例如 Windows/Adobe 实机、独立审计或许可核验。
3. 交接只传“任务 ID + 当前 SHA + 产物/失败证据 + 下一动作”，不传模糊的长对话总结。接手者先运行 `verify-task-state`，不从旧 handoff 猜状态。
4. 审计器不改实现；它检验当前 SHA 和证据，再决定通过/打回。审计通过后才合并或提升状态。
5. 同一 PR 不混入目录大迁移、算法改写、依赖全升级和宿主功能；每个 PR 可回退、可单独验收。

## 物理与数据边界

- 默认工作根由项目解析器决定；运行临时数据在 `.project-local`，用户项目工程在显式作品库，模型在显式缓存根。三者不可互相假设。
- E 盘和用户未授权位置不扫描、不写入。凭据、会话、模型、原始用户工程不入 Git。
- `.gitignore` 只解决提交污染，不证明没有磁盘越界写入。每个启动入口须有路径诊断；Windows 宿主测试须记录写入进程和目标根。
- Comfy MCP 连接、模型下载、云端付费、批量执行和外部传输均记录实例/目标、范围、批准依据与输入输出 hash；默认本地、最小权限，普通任务不得扩大为云端或外传。
- 宿主控制优先级不可倒置：官方 API/脚本优先，UIA tree 次之，视觉鼠标键盘只作人工确认的后备。UIA 首个试点只操作副本，且只允许读取、打开副本、导入、导出新文件。

## 通过门

| 类型 | 最低通过证据 |
|---|---|
| 纯 Python | 修前失败的回归测试、修后通过、锁定环境、可回退迁移 |
| 前端 / 服务 | 用户页面真实调用本地服务、刷新/重启恢复、失败信息可见 |
| Adobe / Blender / Premiere | 真实软件版本、输入工程副本、操作日志、保存、关闭重开、结构读回和产物 hash |
| Comfy / 模型 | 实际 workflow、模型/节点版本与 hash、输出、取消/断线行为；缓存不等于推理成功 |
| Comfy MCP | 实际命名本机实例、server/client 版本、工具清单、完整工作流记录和请求范围；beta 配置不等于连接通过 |
| H3 | 许可/地域适用性与本地实际推理均通过；两者任一未清不得执行 |

任何“CI 绿”“Schema 解析”“README 已写”“截图存在”均不单独构成宿主通过。
