# 全部对话决策收束

## 一、项目定位演进

项目最初被定义为 Open Design 的资料、提示词、模板、样板和配置增强仓。审计后确认，这一定位能够避免重复开发 Open Design，但不足以支撑“全面帮助 AI 完成商业设计”的目标。

最终定位锁定为：

> **OPEN-DESIGN-Assistance 是 Open Design-first、Agent-compatible 的商业设计智能、视觉质量、专业生产与交付增强层。**

Open Design 负责项目、画布、运行时、模型和产物；Agent 负责推理与执行；本仓库负责专业设计方法、风格判断、质量门槛、生产预检、交付合同、案例和评测证据。

## 二、能力范围

必须覆盖并逐步达到可交付：

- 平面与整合传播
- 品牌策略、VI、KV 和跨媒介视觉系统
- UI/UX、网站、应用和设计系统
- 视觉设计与艺术指导
- 产品、电商和商业摄影视觉
- 文化墙、展厅、展陈和环境图形
- 包装、印刷和货架视觉
- 编辑出版和长文排版
- 动效、动态品牌和视频视觉
- 3D 产品、空间、材质与灯光
- 插画、角色和 IP 系统

## 三、视觉质量重点

用户明确要求主要增强：

- 设计质量
- 设计感觉
- 视觉质感
- 各种风格的分析与研究
- 大师级设计的质感、方法和思路
- 去 AI 味、真实感、商业可用性和最终落地

因此不能只堆 Prompt，必须建立参考 DNA、风格谱系、大师方法证据、构图与字体、色彩材质光影、视觉 Jury、真实性检查、微观精修和跨格式一致性闭环。

## 四、大师与风格使用原则

- 所有年代、地域、媒介和专业领域的大师、工作室、流派都可以进入研究发现层；
- 名字数量不是完成标准，必须有身份、来源、作品、时期、例外和失效条件；
- 研究大师是为了抽取可迁移的决策方法，不是复制标志性作品；
- 最终生成指令必须匿名化，不直接要求“某大师风格”；
- 项目与品牌 DNA 占比至少 50%，大师方法合计原则上不超过 35%；
- 标志性 Logo、字体、图形、摄影、版式、建筑、服装、角色和作品元素进入禁止复制清单。

## 五、开源与资料吸收原则

- 尽可能全面发现网站、规范、论文、开源项目和设计资料；
- MIT/Apache/CC0 等明确许可的小型结构可改写吸收；
- 大型工具通过 Adapter 调用，不整仓复制；
- GPL/AGPL、非商业许可和重量级依赖与核心隔离；
- 标准和品牌手册只提炼通用规则，不复制受保护文本；
- 来源或许可不明先 quarantine，禁止自动进入 Agent 上下文；
- 所有来源记录版本、用途、许可、风险、集成方式和晋级证据。

## 六、商业落地原则

每个完整项目必须形成：

```text
Brief → 调研 → 策略 → 三方向 → 用户选择 → 设计系统
→ 多产物生成 → 专业评审 → 有界精修 → 生产预检
→ 可编辑交付 → 案例记录 → 评测与经验回写
```

交付不能只有图片，还要有可编辑源、预览、字体与素材清单、尺寸色彩、版本、生产说明、评分、预检、BOM 和 provenance。

## 七、执行和安全原则

- HERMES 是唯一用户入口和总控；
- 同一 checkout 同一时刻只有一个 writer；
- Codex 默认作为代码 writer，高风险候选由全新只读 Codex reviewer 复审 exact tree；
- GitHub 是远端分支、PR、CI 和交付证据事实源；
- Windows 原生优先；
- 所有缓存、日志、测试、备份和评审输出进入项目 `.hermes/`；
- 默认 dry-run / plan，不自动 live apply、commit、push、PR、merge 或 release；
- 禁止删除项目外文件，禁止访问和修改 E 盘，禁止读取任何凭据。
