日期：2026-09-29。性质：本对话全部研究、补回与更正的综合判断；不是新 Authority，不是实施授权。证据基线为本对话已核验的 main `010f6a57610214fa41651861e00319f88a2f49a4`；本次整合不声称重新执行实机测试或刷新所有云端状态。

## 1. 最终判断

DESIGN-LAB 值得继续推进，正式定位无需推倒重来：**面向职业视觉设计的 AI 原生、平台中立、宿主原生设计智能与生产能力层。** 当前主要矛盾是已有专业方法、质量体系、适配与代码尚未形成用户可连续操作、可恢复、可编辑交付的产品链。下一阶段应从反复扩大规划转向商业级个人工作台和真实设计生产闭环。

保留 DESIGN-LAB Lite 工作台、Host Launcher 和设计域 MCP/代理诊断；不要将其变成通用 Agent OS。以9/28商业级前端与能力闭环任务包作为最新产品增量输入，以云端Authority和现有账本管理实施，以Master Atlas保存历史、长期蓝图与候选池。三者各司其职。

历史原件尚有缺口，但已取得的材料足以支持产品边界与近期执行判断。缺口只限制“完整原始历史恢复”声明，不应阻塞已有任务落地。

## 5. Lite、Launcher、MCP控制台的最终边界

**Lite应是正式产品的默认轻量入口，而不是另一个产品。** 使用同一项目、资产、任务和证据模型；高级功能渐进展开。

| 功能 | DL拥有的范围 | 外部边界 |
| --- | --- | --- |
| Project/Brief/Asset UI | 创建、版本、引用、授权、方向与交付 | 不跨项目直写私有数据 |
| Host Launcher | 启动用户已配置设计宿主和项目；展示路径/版本/资格 | 不自动安装、不修改所有客户端全局状态 |
| Capability Browser | 域/工具/模型的输入输出、资格、限制、证据 | 历史候选不能显示为已可用 |
| Host Adapter状态 | 连接、权限、执行、回读、取消、恢复 | 进程运行不等于资格通过 |
| Model/Tool状态 | 设计参数、能力资格、模型版本、资源需求、fallback | 不建设第二共享模型服务或全局网关 |
| MCP诊断 | 设计端点schema、超时、错误、取消、脱敏日志 | 全局MCP注册、client/plugin配置归WORK-LAB |
| 设计workflow | Brief到设计、审查、预检、交付的领域流程 | 通用Agent调度和跨项目协调归WORK-LAB |
| 知识桥接 | 批准的KnowledgeCandidate与证据引用 | 知识治理归ArcheAxis；原始素材不默认外发 |

Open Design始终是外部client/host adapter。用户级workflow/plugin state可由WORK-LAB管理；设计对象、参数、质量门与交付由DESIGN-LAB拥有。支持MCP也不自动意味着可以使用网页GPT额度或控制网页会话；那是外部客户端与授权契约问题。

## 6. 商业级个人使用前端的正确路线

判断：保留当前strictTS架构，集中做一个连贯可用的产品入口；暂不整体迁移React、Avalonia或桌面壳。平台选择由确切需求和ADR驱动，不以换框架代替质量改进。

9/28方案的Spectrum Web Components首选、Web Awesome Core备选，应保留为**兼容试验顺序**，不是已经选定或已集成。用相同10类控件测试：生产Python服务、wheel安装态、CSP、Shadow DOM、中文IME、键盘和焦点、离线资源、构建契约、实际包体与启动开销。过关后选一个主体系；未过关则保留现有控件并记录明确原因，避免无限选型。

成熟组件能减少交互与可访问性重复建设；但其存在不自动补齐Project/Brief/Jury等业务模型。W02所谓46项中25covered等计数仅是该审计口径，不是商业成熟证书。

近期界面缺口优先级：

1. 真实项目工作台：保存、失败、恢复、版本冲突，禁止假KPI。
2. 参考与资产：不默认裁切，透明度可见、来源/rights、完整预览、部分失败和项目隔离。
3. Direction与DesignSystem：对象表单、约束、版本、Token写入与回滚。
4. 生产任务：真实状态、取消ACK、重试attempt、宿主缺失/权限/版本解释。
5. Review/Preflight/Deliveries：拒绝→修订→重审、失败定位→修复→复检、源文件重开。
6. Windows使用质量：2560×1440及缩放、中文IME、键盘/读屏、离线、安装与重启恢复。

工作台品牌Token与客户项目DesignSystem必须分开。延续已有效采用的DL视觉资产；B04/B07/B10之间字体、圆角、断点、动效冲突按当前有效决策解决，不能仅按包日期自动覆盖。用户要求的一比一继承以实际可见原件为基础；自生成替代图标注为替代，不冒称原件或逐像素一致。

## 7. 视觉质量体系的判断

V2.1的120个文件中87个在当前树中保持字节一致，33个有同名演进候选，不能将目录迁移误判为质量体系被删除；也不能据此认定全部语义和调用链完整继承。

应保留24轴、四类质量维度、确定性/感知/专业判断三层证据、多角色Jury、anti-AI-artifact、跨格式一致性与生产就绪。旧82分、盲评偏好70%等属于历史特定profile，不是所有专业设计通用认证。权利、字体、链接、尺寸等硬失败不能被平均分覆盖。

真正缺口是将这些规则绑定到用户实际作品版本：指出对象和问题、支持局部修正、重新运行检查、独立专业接受，并将结论随可编辑交付一起保存。VLM或Jev评分只能辅助；同一执行模型自评不能升E4。

## 8. 宿主、模型与扩展池排序

| 阶段 | 对象 | 裁决 |
| --- | --- | --- |
| 首条生产链 | Photoshop或Illustrator择一先跑 | 单宿主先成功；既定M1双宿主等依赖仍须满足，不静默降标 |
| 第二阶段 | 补另一Adobe；Comfy图像/透明资产；Figma或Penpot一个试点 | 每次引入一个可验证能力及失败场景 |
| 条件扩展 | ChatCut、Premiere/AE、Blender、包装/出版/展陈、游戏视觉 | 真实业务驱动，保留源工程/依赖/rights |
| 模型专项 | MiniMax H3、Qwen图像、视频/3D模型 | 独立资格，不默认安装或成为项目启动依赖 |

MiniMax Design是外部创作客户端，H3是模型能力，ComfyUI是生成执行sidecar，官方插件是工具连接层；四者不能混为一个产品或许可证。H3 hosted IR与本地Base分开，已存权重不证明完成加载/推理。本地8GB显存是实际约束，64GB内存不能当作显存等价替代；本报告不提供未经实测的运行承诺。

DL消费已批准共享模型服务，保存实际provider/model与provenance；是否使用LM Studio、Ollama、llama.cpp由共享运行环境治理决定，不要求DL全部安装。AI失败时手工编辑和已有宿主生产应能继续。FAST/DEEP是逻辑能力档位，不锁定厂商、模型或执行器。

已有44项本轮上游候选与162项历史隔离池继续保留；ChatCut补入历史候选。候选数不能相加当作不重复“已吸收数量”。license、模型权重、插件、字体与服务条款分别审核；未知与受限项保留BLOCKED，不默认商用。

## 9. 最短可用闭环与任务收敛

首个验收项目应选用户已有业务中的一项，例如单页海报、展架或品牌视觉物料，使用授权素材和用户指定尺寸。选择标准是能验证真实可编辑输出，而不是哪一个模型演示最炫。

流程：创建项目→Brief→参考与授权→方向选择→设计系统→可修正对象计划→宿主生成→局部改字/换图→readback→人工拒绝并修订→预检故意失败并修复→交付源文件/预览/BOM/rights/provenance→关闭重开→继续编辑与恢复。

| B | W04–W06 | 不重写已有导入/方向/绑定；补实际缺口，尤其Token版本闭环 | 参考、方向、Token编辑及重启读回 |

原41项→W00–W17的映射在9/28包中已存在，应复用。Master Atlas的CAND-01至10也是建议分组，不再加成第三份实时账本。最终实施状态只写既有DL-R5 machine ledger。

## 11. 最终行动结论

**继续现有产品方向，收敛执行，不收缩历史能力。** 先交付商业级个人工作台与一条真实Adobe可编辑生产链，再按真实业务扩大宿主和模型。Lite必须留下；全局控制交给WORK-LAB；专业质量与交付由DESIGN-LAB负责；批准后的知识交给ArcheAxis。
