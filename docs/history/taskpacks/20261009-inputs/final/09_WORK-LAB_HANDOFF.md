# 交给 WORK-LAB 的提示词

请把以下作为 WORK-LAB 与 AAOS、DESIGN-LAB 的最新长期协作要求，与本项目定位、工作流、执行证据、知识候选、前端与公共合同对账。不要把WORK-LAB降为调度器，也不要扩成其他项目总控制器。请在本项目已授权范围落地必要改动与验收，不只增加规划报告。

WORK-LAB 从AAOS获取获准的编程、AI、自动化和治理知识，并在真实工作中整理方法、故障原因、无效方案、修复过程、环境/版本差异、适用条件和反例。保留来源、运行依据、局限和用途，提炼为知识候选交AAOS管理长期知识/版本；不再造通用知识主库。命令成功、文件存在、业务完成分开，原日志不自动成为知识。

新增联合路径：WL实践经AAOS组织知识与学习目标，由DL制作流程图、视觉讲解、动画、操作演示、互动练习和课件，再由AAOS实际学习、记录与评价。WL提供获准真实案例、可复现技术示例与边界说明；学习问题回知识、技术、设计/教学和运行的相应负责人，形成修订。没有实际运行的示例标假设，同源媒体不能伪装独立证据。

DL是全品类专业设计知识应用与自动化系统，能有自有设计专用执行循环，也能调用外部Agent与现成软件。WL按需提供任务协调、环境、权限、预算、并发和恢复，不接管设计判断、原生作品或AAOS知识/学习状态；Observer只读，不执行/批准/修改。DL/WL/AAOS可以直接按需协作，不要求每次绕行三方。

复用任务/证据/候选机制，明确知识获取及版本、经验提炼、候选提交/回执、教学案例提供、技术复现、反馈处理。候选可以未核验先保存；一次成功、模型自评、偏好不直接升级通用方法或执行资格。知识/工具/任务/教学内容版本和失败不确定性如实记录。

协助同桌面/宿主/文档租约，API与GUI也可能互相争用；推理并行不意味着多Agent同时抢Windows桌面。超时先对账、幂等键绑定输入、预算截止、重启恢复和人工接管都应有真实行为。没正式API的消费级Agent不冒充后台无人值守适配。

各自DB与三仓独立，AAOS正式写知识，DL写配方/制作源，WL写工作与证据。离线有获准快照及本地恢复；不保持两份可编辑知识主版本，不默认迁移客户/私人会话/凭证/未授权资产，标题/缩略图/片段等也不能出域。低风险已许可工程持续推进，真实人审和高风险决定不能代签。

同步校正前端实际工作/证据/候选/教学支持入口，以及当前权威、配置、Agent规则、任务、生成器、测试和部署投影。保全历史原件、解除旧入口效力、不重置全账本。不能只改文字后让旧测试和规则把实现拉回去。

首例建议《任务显示成功，为什么还不一定算完成？》。提供实践来源→AAOS知识/目标→DL教学→AAOS学习/题目反馈→WL技术改进与回执。只有合同/报告就标部分完成，至少一轮真实修订才算联合闭环。

输出职责增量、现有模块映射、旧定义冲突/替代、接口缺口、实际改动、技术验证和联合验收证据、未检查部署副本与阻塞。当前交接不自动授权改另两仓、迁移全库、安装、付费或发布；继承已明确许可，不因历史文件中模糊限制停掉已授权可回滚任务。
