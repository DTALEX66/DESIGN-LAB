# 本轮决定与旧结论修正

日期：2026-10-09。用户最新意图优先用于规划；下列不会自动修改代码或原有仓库规则。

| 对话阶段 | 当前应保留的含义 | 修正／不应继承 |
|---|---|---|
| 审计闭环 | 找真实用户任务与交付断点 | 不把CI绿色当产品完整 |
| 审视界面 | 问题包含产品形态与过度治理 | 不再机械补齐12导航 |
| 用户澄清不是工作台 | 能力资产与需求响应是中心 | 前面的项目工作台建议降为历史探索 |
| 全品类资产与方法 | 全设计品类是长期范围 | 首批案例不是永久缩窄范围 |
| 现成设计软件 | 不造画布/编辑器/渲染器 | 不等于禁止适配器和原生操作服务 |
| 无法自动操作时给提示词 | 提示词/执行包是正式输出 | 用户要原生工程时，回提示词仍是未完成 |

| 自有自动化更强也可以 | 允许并建议有界设计执行内核 | “只能给别的软件当资料包”不再成立 |

## 应明确修改的旧表述

1. “不做通用Agent runtime”可保留，但要明确允许设计专用的规划、动作执行、检查和恢复循环。
2. “不做工作台”指产品中心，不是删除必要的运行状态、预览、批注和取消操作。
3. “不造视觉设计软件”不禁止本项目通过Adobe/Blender等接口生成原生内容。
4. Figma普通插件生命周期与官方MCP写入是不同接入方式；新路线必须同时考虑，不用旧限制推断全部能力。
5. React只是可选工程手段，既不是新定位前提，也不是当前已批准的强制全量迁移。
6. 分类整理、知识保存、接口验证和最终人审采用不同标准。知识条目不能被一律要求真实宿主验收。
7. AAOS保存长期知识；DESIGN-LAB仍负责设计专业语义、运行配方与验证，不能退化为一个搜索UI。
8. 独立可用与联合知识并不矛盾：固定授权快照＋公共合同，而非两份可任意编辑的知识主库。
