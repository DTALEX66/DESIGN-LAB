# DESIGN-LAB × AAOS：联合架构与能力资产蓝图

日期：2026-10-09  
文档性质：基于用户最新定位的产品与架构增强建议。不是已完成的迁移报告，不是已部署接口，不自动替代仓库 Authority，不授权删除、跨项目写入、安装、软件执行或发布。

## 0. 本轮已明确的产品目标

DESIGN-LAB 不是项目工作台，不是另一个视觉设计编辑器，不复建 Open Design、MiniMax Design 或专业软件的画布。它面向全设计品类，组织和调用规范、方法、风格、案例与制作能力；理解截图、文件、音视频和文字需求，输出目标软件可用的设计提示词、执行方案，或调用现成软件产生可验证的原生工程与最终媒体。

未来必须与 AAOS/ArcheAxis 联合；长期知识应逐步交给 AAOS。全品类是产品范围；不同领域的软件自动化深度可以分阶段验证，不能以首个案例代替完整定位。

本轮只读核对的远端基线：
- DESIGN-LAB main: fc03a3033e900a8066d863a223636cc68804c4fa
- ArcheAxis-Knowledge-OS main: 4b9828c4058901c0b1fd2c75c528238c55e0ec89

## 1. 总体裁决

两个独立产品，一份长期知识基础，一个设计专业能力层，多种现成生产软件。

AAOS 管长期保存、来源、版本、知识关联、通用检索及人机学习。DESIGN-LAB 管设计领域语义、输入分析、方法选择、提示词适配、执行配方、软件适配及产物检查。原生作品由所属用户/设计任务及专业软件持有，不因为进入联合目录而整体搬进 AAOS。

知识存储归属不等于专业编辑责任。设计方法可以由 DESIGN-LAB 提议、整理和专业修订，通过 AAOS 公共写入合同保存；不是只有打开 AAOS 界面才能维护。两端不得各自维护同一条知识的独立可编辑主版本。

## 2. 资产归属

| 对象 | 长期主存储/事实所有者 | 专业维护/消费 | 边界 |
|---|---|---|---|
| 授权研究资料、教程、案例解释、知识笔记 | AAOS | DESIGN-LAB 提供领域分析 | 客户和受限资料不默认入库 |
| 设计概念、风格特征、规范与方法正文 | AAOS | DESIGN-LAB 维护设计语义并经 API 提交修订 | 区分正式规范、经验规则与偏好 |
| 方法执行配方、目标软件提示词模板、脚本、适配代码 | DESIGN-LAB 的版本化能力包 | DESIGN-LAB | 引用 AAOS 知识 ID/版本；AAOS 可索引而不接管执行源码 |
| 已部署规则/知识片段 | DESIGN-LAB 有界只读快照 | DESIGN-LAB | 是可追溯派生物，不是第二知识主库 |
| PSD/AI/三维工程/音视频工程/最终媒体 | 所属设计任务和用户指定资产位置 | 现成专业软件与 DESIGN-LAB 适配器 | 不默认复制到 AAOS；索引也须权限许可 |
| 临时上传、执行事件、任务恢复记录 | DESIGN-LAB 的任务域 | DESIGN-LAB | 不当成长期知识，不自动外发 |
| 经授权且可复用的纠正与经验 | 先是候选，再由 AAOS 保存与治理 | DESIGN-LAB 提交、AAOS 管版本 | 客户隔离优先，脱敏不等于出域授权 |
| 全局学习记录与跨任务偏好 | AAOS | DESIGN-LAB 按任务使用 | 单次偏好不自动升级为全局规则 |

共享模型和大型素材保留既有存储归属，不因联合新建一套权重库或统一业务数据库。知识复制、缓存、备份应显式登记，禁止含糊的双主同步。

## 3. 完整运行链

输入 → DESIGN-LAB 识别目标与约束 → 向 AAOS 请求许可范围内的相关知识 → 固定上下文版本 → 选择方法与软件能力 → 输出提示词/执行包/实际调用 → 检查产物 → 收集纠正 → 形成授权候选 → AAOS 版本化处理 → 新版本方法经再验证成为后续能力包。

普通创意草稿可以先保存、阅读和探索性使用。保存、正确性、专业认可、权利可用性、可执行性和正式交付是不同判断，不得用一个通过状态替代。

新知识不在执行中自动改写正在运行的任务。每次任务固定知识、配方、适配器及必要目标版本；新增内容用于下一次或明确重算的任务。已知撤销/禁用项不得作为新任务输入；有强制新鲜度要求的场景，离线时不能宣称已经检查最新状态。

## 4. 三次转换

### 4.1 资料转知识

AAOS 承担通用原件、版本、解析和定位；DESIGN-LAB 贡献设计语义，例如风格特征、构图策略、例外和适用条件。并非所有截图都应入 AAOS：一次性任务可只在 DESIGN-LAB 任务范围处理；客户文件继续隔离。一般解析器可以复用，数据不能因此自动共享。

观察事实、来源直接陈述、模型推断、个人偏好分别记录。截图重建无法证明恢复了原工程，不可观察结构标记为未知。

### 4.2 知识转能力

选中的方法形成能力包，至少描述：解决的问题、适用输入、前提/限制、可调参数、生成或制作步骤、工具绑定、交付要求、检查方式、失败降级及知识来源版本。

能力包是部署单元，不是每个领域新建一套应用。一个能力包可有提示词、脚本和人工操作三种出口；同一知识可被多个能力包复用。

### 4.3 能力转目标软件输出

输出类型须由需求决定：分析、提示词、执行包、实际生成、原生工程可分别完成。要求 PSD 而只得到提示词时只能标替代方案。目标软件没有生成式输入时，提供操作方案或脚本，而不是声称粘贴自然语言即可自动制作。

实际可编辑性按对象/图层/路径/场景/时间轴和依赖验收，不按扩展名验收。未验证操作不给自动执行资格。

## 5. 全品类与分类模型

保留品牌、平面、字体、出版、包装、空间、交互、三维、动效、视频、声音、游戏视觉等范围，不把它们全部提前做成独立导航或独立软件模块。

分类采用组合维度：
- 设计领域与使用场景。
- 感知特征：构图、字形、色彩关系、纹理、空间、运动、声音特性。
- 风格/流派及其证据、不确定性与混合关系。
- 设计方法和适用条件。
- 输出格式和要求的编辑粒度。
- 软件/接口/版本/硬件及人工参与要求。
- 知识、提示词、自动化、原生交付的实际可用范围。

AAOS 维护统一概念标识、别名、关系和版本；DESIGN-LAB 维护设计领域定义及方法适用性。领域扩展映射到共同概念，不另造无法互通的第二套总分类树。

可借鉴 SKOS 的概念标识、首选/替代标签、上下位与关联关系；不强制新增 RDF/图数据库。可借鉴 PROV 的使用、生成、派生、修订和失效语义；不要求先实现整个本体系统。

## 6. 双向接口：先做三个语义能力

下列是建议契约，不是已存在的端点名称。

| 语义能力 | 方向 | 最小作用 |
|---|---|---|
| 取知识上下文 | DESIGN-LAB → AAOS | 查询/读取授权知识及指定版本；返回有限上下文、依据、范围与限制 |
| 提交知识候选/修正 | DESIGN-LAB → AAOS | 提交经允许的观察或方法修正；幂等受理，不自动成为已验证知识 |
| 回执与变更读取 | DESIGN-LAB ← AAOS | 读接收结果、新 revision、冲突、拒绝、撤销与失效信息 |

通用字段建议复用现有对象而非另建平行 schema：记录 ID、revision、内容 hash、来源定位、生产者/原作用域、用途权限、状态、不确定性、必要新鲜度信息、父版本/替代关系。

候选写入还需要 request ID/幂等键、基准版本和内容摘要。同一个键同一个内容返回同一受理结果；同一个键不同内容显式冲突。写入由 AAOS 自己的正式 writer 执行。

初期用版本化 JSON 合同及有界本机接口，或显式导入导出包。普通轮询可满足第一批回执与变更获取；不先建消息中间件或分布式事务。

MCP 可作为读取知识资源与调用设计工具的接入方式，但不是知识库，不负责替代权限、来源可信度和版本治理。协议适配不得让知识里的脚本或安装命令自动获得执行权。

## 7. 离线与降级

可在 DESIGN-LAB 内抽象一个窄的 KnowledgeProvider：临时本地快照与 AAOS 实时提供方实现同一读取合同。它不意味着再建通用向量库、笔记编辑器或知识图谱引擎。

AAOS 不可用时，已有授权且适合该用途的固定快照可用于分析/提示词/允许的任务，并显示来源版本及新鲜度。未知权利、已撤销内容或要求在线复核的高风险操作不能假装通过。

符合出域条件的反馈进入本地待发送队列，恢复后幂等提交。禁止出域的客户材料不能因为网络恢复进入队列。

新内容可先保留为明确的本地候选/草稿；不能把长期暂存演变为第二个可编辑主知识库。

## 8. 双向学习闭环

例如用户在一张授权测试图上纠正“这是编辑式排版，而不是科技风”：
1. DESIGN-LAB 记录这次判断和纠正，保留任务范围。
2. 形成候选解释及对应输入依据。
3. AAOS 保存候选，不直接把一次判断变为普遍规则。
4. 经适用性核对后更新方法版本或加入反例。
5. DESIGN-LAB 对相关分析/提示词配方运行对照案例。
6. 改善成立后发布能力包新版本；退化则保留旧版本。

同时支持两种结果：为人组织原理、反例与练习；为模型提供更明确的检索上下文、约束和操作配方。知识回流不是已经训练了模型权重，也不应宣称只要收集更多资料就会自动提高审美。

统计至少分开：来源可追溯性、分类解释质量、提示词目标适配、软件操作成功率、原生结构合格率、人工返工，以及再次调用是否改善。使用量不是质量证据。

## 9. 前端：联合能力目录，不是大型工作台

主要界面：
- 能力资产库：领域、风格、方法、案例、模板、目标格式、可执行范围。
- 分析与生成：上传/描述 → 自动判断或选择目标 → 结果与可执行动作。
- 历史与纠正：查看之前的分析、提示词、产物和授权回流状态。

设置内放软件连接、AAOS 连接、版本/权限与诊断。执行进度是本次任务的附属面板，而不是首页主体。

一张能力卡可联合展示 AAOS 方法正文、DESIGN-LAB 配方/测试、授权案例与本机软件资格。搜索和展示可以统一，数据不必物理集中。编辑知识通过 AAOS 公共写入合同；复杂知识阅读/关系维护可跳转 AAOS，不再造一个通用笔记编辑器。

结果页先给有用答案：判断、依据、所选方法、目标提示词或可执行方案。来源、版本与局限可展开，但关键风险和缺失条件必须可见。普通用户无需填一堆知识治理表单。

## 10. 安全与资料隔离

客户材料、私人会话、未授权字体/图片/模型及敏感执行信息不默认进入 AAOS 或公共能力池。匿名化与删除名字不是新的授权。任何例外都必须另行有明确适用授权和内容审查；当前客户隔离规则未被本蓝图放宽。

权限过滤要发生在检索结果产生之前及输出/执行之前，避免通过标题、缩略图、片段、数量或引用泄露受限材料。去重不应跨权限域泄露某个文件是否存在。

第三方文档中的 AGENTS、SKILL、安装命令和脚本是未受信输入。知识候选与可执行能力分离；执行包只有在来源、版本、允许操作、数据范围及相应测试成立后才可调用。

每次操作对作用文件和覆盖范围可见。优先在副本或任务目录执行；不关闭共享宿主、不覆盖无关文档、不默认外传输入。高风险动作的确认与普通只读/可回滚操作分开，不把所有步骤都变成人工审批。

## 11. 现有项目如何调整

保留 DESIGN-LAB 已有 Python 服务、原生任务、格式合同、校验、适配和版本恢复基础。将项目工作台中心叙述改为能力资产/分析/交接中心；不因为否定旧页面定位而删除底层任务和证据能力。

不重新建设通用摄取、笔记、长期检索和学习系统；这些由 AAOS 承接。允许复用已有解析库和任务内短期处理，不能把“复用基础能力”误等同于“发送所有用户文件”。

当前 docs/architecture/BOUNDARY_CONTRACT.md 仍把 apps/workbench 指定为唯一设计控制面，因此有明确的目标文档差量需要登记。修改应是一份定位与职责的增量替代记录及对应实现映射，不再叠加一套自称最高权威的平行蓝图。

WORK-LAB 只在需要跨 Agent/跨项目调度时提供公共执行治理。AAOS 查询与知识回流不强制经 WORK-LAB 绕行，DESIGN-LAB 的设计语义与验收也不外包给 WORK-LAB。

## 12. 分阶段实施与迁移

### A. 先确定边界与窄合同

复用并盘点已有 KnowledgeCandidate、来源/方法/能力对象。划分知识、执行资产、作品、缓存和受限内容。确定统一知识引用、上下文读取、候选受理及回执合同。通过一个允许共享的样本跑通往返；接口存在不等于所有知识已迁移。

### B. 两条产品能力并行

提示词链：截图/文件 → 相关知识 → 专业分析 → 目标提示词 → 纠正候选。
自动化链：设计目标 → 知识/配方 → 合格软件适配 → 原生工程 → 重开核对 → 经验候选。

按多个代表品类设置案例，记录每种输出的真实覆盖，不让第一条图像案例代表音视频/三维全部完成。自动化未就绪不阻止提示词能力，提示词完成也不替代工程交付。

### C. 分批迁移知识主存储

1. 分类并建立迁移清单，客户/受限内容排除，不扫无授权外部根。
2. 保留旧 ID、原字节、来源与引用；为每条建立旧 ID → AAOS ID/revision 映射。
3. 导入后逐项读取，核对内容 hash、来源定位、知识关系、权限和用途。
4. 将 DESIGN-LAB 的知识读取切向 AAOS/有界快照；该批旧知识源改为只读，停止双主写入。
5. 修改从 DESIGN-LAB 发起时，通过 AAOS 正式接口处理并返回 revision。
6. 断网、重试、重复提交、版本冲突、撤销及恢复都通过后，该批才算切换完成。
7. 旧包作为恢复档案保留；删除和大文件清理另行授权。

不等待 AAOS 的 XR、所有知识平台互通或所有学习功能全部完成才联合。只要求本次联合所需的保存/读回/引用/候选回执边界可靠。

## 13. 联合验收矩阵

| 案例 | 通过条件 |
|---|---|
| 知识引用 | DESIGN-LAB 能用许可范围内的 AAOS 指定版本生成分析并展示依据 |
| 全品类定位 | 多领域代表案例各有真实报告；未测领域不被写成已验证 |
| 提示词交付 | 输出适配选定目标；未知参数与结构限制明确；不是通用长提示词 |
| 原生交付 | 实际生成目标结构，重开可检查；文件扩展名不足以通过 |
| 候选回流 | 允许的纠正经 AAOS 受理并返回回执；重复提交不重复建知识 |
| 双向版本 | 更新用于后续任务；在途任务固定版本；已知撤销影响新调用 |
| 隔离与权限 | 客户/受限数据不跨域，包括输出片段与元数据 |
| 离线与恢复 | 合法快照可继续；超出资格诚实降级；待发回执恢复后不重复 |
| 迁移 | 旧新 ID 映射、字节、来源和引用可核对；仅一个知识写入主源；有恢复入口 |
