# 三项目最小公共合同

以下定义语义，不宣称已有同名API。先查现有KnowledgeCandidate、任务、产物和课程对象及公共接口，复用已存在合同，必要字段增量。初期版本化JSON、现有本机接口或显式导入导出包即可，不先引入消息总线、共享DB或分布式事务。

## 1 归属

| 对象 | 主责 | 其他项目的作用 |
|---|---|---|
| 长期知识正文、来源、关系、版本 | AAOS | DL贡献设计语义；WL贡献实践/验证 |
| 设计执行配方、软件适配和能力发布 | DESIGN-LAB | 引用AAOS知识，可委派WL/外部执行器 |
| 实践任务、执行证据与技术复现 | WORK-LAB及真实执行模块 | AAOS存获准候选，DL用于设计/教学 |
| 原生设计工程与制作源 | DESIGN-LAB任务域/用户指定位置 | AAOS登记允许引用，不默认复制 |
| 教学课程、知识关联、练习、长期学习状态 | AAOS | DL制作表达/互动；WL校验技术案例 |
| 设计质量评审与交付判断 | DESIGN-LAB相应规则及真人 | 外部检查不能代签真人 |

## 2 六种公共语义

| 合同 | 发起/接收 | 最小字段与行为 |
|---|---|---|
| 知识上下文读取 | DL/WL→AAOS | 用途、域、范围、所需revision；返回ID/revision/hash/来源定位/依据/适用限制/许可用途/新鲜度 |
| 候选或纠正提交 | DL/WL→AAOS | 幂等键、内容摘要、基准revision、观察或方法、证据/反例、环境、适用条件、允许回流范围；受理不等于批准 |
| 回执与变更读取 | AAOS→消费方 | 候选ID、受理/冲突/拒绝/核验状态、revision、替代/撤销/失效；便于重试与后续能力再验证 |
| 教学需求 | AAOS或获准委托方→DL | 人群、前置、目标、知识/来源版本、重点误解、约束/形式、验收和反馈需求；简单图解省略无关字段 |
| 教学成果交付 | DL→AAOS | 内容/源工程引用与版本hash、讲解文本、字幕/必要视觉描述、练习反馈规则、知识映射、运行依赖、限制与核验 |
| 学习和生产反馈 | AAOS/DL/WL→对应责任方 | 知识版本、内容版本、场景/题目/任务、实际观察、证据、改进许可、类别/责任方、修订关联与处理回执 |

运行任务引用知识、配方、模型/工具、宿主/适配器、输入及产物版本。知识修订不静默改变运行中工程。若同键同内容重复提交返回原受理结果，同键异内容明确冲突；断线队列恢复不重复写知识。

候选可以尚未验证而保存；正式教学与自动执行资格分开。原始日志不等于已提炼知识，个人偏好不等于规范。同源派生成果记录共同source lineage，不当独立证据；新的学习/实践观察是观察，是否支持通用知识修订另行判断。

## 3 权限与独立恢复

各项目只写自己业务域；知识正式writer由AAOS控制。Observer只读。教学代码与内容没有桌面执行权限；播放或互动中出现脚本/命令不能继承生产侧权限。

客户原件、Brief、私人会话、凭证和未授权资产不默认迁移；标题、摘要、缩略图、引用、向量索引、计数和去重也不能跨域泄露。知识保存与执行包资格分离，第三方文档/AGENTS/SKILL/安装命令不可授权运行。

独立模式用授权有限只读快照、任务恢复状态和已许可能力；不是第二知识主库。AAOS不可用时依据新鲜度/撤销/用途降级，需在线复核项不能伪装通过。获准反馈暂存，未获准内容不得放入待外发队列。三仓可按不同节奏发布，不把所有直接协作强制绕三方。

## 4 联合案例逐步验收

1. WL提供可复现、可授权真实材料；成功信号、失败、修复、环境和局限分别记。没有真实材料则内容标示例/假设。
2. AAOS生成版本化知识、来源、前置、目标及练习要求。
3. DL据学习目标选择图解/演示/动画/互动；专业简化保留语义并标注；提供文本、必要视觉描述、可修改源及依赖。
4. AAOS实际加载内容，呈现练习并记录回答/解释/应用；播放记录只表示行为，不表示掌握。
5. 至少一条实际反馈定位到知识/内容/题目，路由至正确责任方，修订并读回新版本。

本项目合同替身和可导入包只证明DL边界；三方实联与真实学习不在就标未完成。没有跨仓许可时提供接收文件与验证方法，不越仓代写。复用成熟组件需要运行承载实测，不能只写“兼容H5P”便通过。
