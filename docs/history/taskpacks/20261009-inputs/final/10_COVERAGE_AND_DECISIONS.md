## 旧说法替代

| 旧建议或歧义 | 当前裁决 |
|---|---|
| 项目首页、三栏工作区、工作台中心 | 能力资产和需求响应为中心；项目结构保留作组织/恢复 |
| 不能自研编辑器所以不能执行 | 不重造编辑器；允许复用已有设计专用运行内核 |
| 只能给外部Agent当资料包 | 自有、委派、混合均可，实际实验选择 |
| 中立所以不能选优先适配器 | 按任务/版本/证据选择；保持可替换 |
| 全品类等于所有软件都已支持 | 长期范围完整，实际覆盖逐项说明 |
| 知识归AAOS所以DL只能搜索 | AAOS长期主版本，DL专业语义、配方、执行与核验保留 |
| 跨项目仅可选未来，因此本批不管联合 | 独立可运行保留；长期联合与教学合同纳入本批；未接入如实标 |
| 任何知识都必须E3或真人批准才能保存 | 观察/候选可先保存；执行/教学/正式交付另核验 |
| Figma普通插件限制等于所有写入不行 | 区分普通插件/官方MCP等表面，采用时核实实际版本权限 |
| React迁移必须先完成 | 复用现有TS/Vite/Python，组件化按实际需要 |
| 一比一UI意味着旧十二菜单/DOM不可改 | 保持已认可品牌语言；不合适信息架构可迁移 |
| 改所有文件到最新就完成清理 | 全量清点、当前更新、生成重建、历史保全并隔离加载 |
| 历史SHA旧所以报告是假/全部未完成 | 按原input/tree-digest与STALE语义检查，不误报 |
| 同源文章/动画/课件互证 | 单一来源派生链，不提升独立证据数量 |
| 三份规划报告等于三方闭环 | 实际内容、学习、反馈与修订才通过 |
