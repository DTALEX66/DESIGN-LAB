## 能力资产不能成为来源登记表

能力卡回答：解决什么问题；输入和示例是什么；能分析、生成、执行还是交付；适用条件是什么。来源、星数与证据可展开，但不能代替产品能力或许可。一个能力可有多个软件实现，UI 不为每个来源造重复模块。

分类透传既有七轴完整值。建议领域、场景、视觉/听觉特征、风格、方法、目标结构与软件条件等维度用于呈现；实际键名以仓库现有七轴为准，不随意覆盖。规范、经验、偏好、软件限制与权利条件各自标识。资格 null 是未知，不能自动解释为失败或合格。

预览中的六卡只是说明信息层级。生产支持长列表分页、搜索、过滤和真实覆盖矩阵，未测试领域显示范围与局限，不铺未来空模块。

## 输入不强迫完整项目流程

简单文本或单图任务可直接分析。交付目标先确认：分析、目标生成包、操作计划、媒体或原生工程；精确文字、锁比例、锁位置、相机/时间关系与编辑范围按输入属性出现。未知图层和被遮挡内容标推断。现有 Project/Brief/Reference/Direction/DesignSystem 做内部接续，不让用户填原始 RIR/JSON。

原创与复刻是需求选项。参考图、结构图、风格图和准确正文各有职责，不能把一个风格参考自动当成内容或授权来源。

## 三方协作在日常任务中出现

AAOS 知识依据出现在能力、分析与成果引用中；教学需求作为制作输入；候选和反馈显示接收回执。WORK-LAB 技术案例出现在教学/复现材料中，必要运行支持出现在执行条件中。无需另建三项目总控台。

课程登记、练习运行与长期掌握状态留在 AAOS。DESIGN-LAB 显示制作状态、知识/内容版本、源工程与修订；不建立学习画像。源工程用获准引用，不复制所有大文件。

## 视觉延续与实现事实

本包以深冷蓝背景、蓝白焦点、银色图形、细边框与紧凑信息为基线。已有 UI 套件和品牌原件必须先核对；源图用于品牌参考，不能根据旧版图中的文字重命名 AAOS。状态语义由 API 驱动，截图上的演示记录必须在生产移除。
