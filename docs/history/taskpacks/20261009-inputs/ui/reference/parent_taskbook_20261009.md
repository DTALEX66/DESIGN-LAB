## DESIGN-LAB 产品定义与执行依据迁移总任务书

本批要实现的变化：让 DESIGN-LAB 从旧工作台中心转向全品类设计能力资产与需求响应；同步当前定义、前端、必要接口、运行能力、任务和验收依据；保全历史证据；通过真实产物及三项目知识和教学反馈验证闭环。

### 1 稳定产品定义

DESIGN-LAB 是面向全设计品类的专业能力资产、设计知识应用与自动化系统。它理解截图、文件、多图、音视频和文字需求，调用规范、方法、风格、案例与经验，将专业设计判断转换为目标生成包、制作方案、原生操作计划或实际产物，并独立检查结果。

长期知识与 AAOS 联合管理，逐步以 AAOS 为知识主版本；DESIGN-LAB 保留设计专业语义与判断、能力包、生成配方、软件适配代码、设计专用执行和产物检查。系统既能被外部 Agent 调用，也能委派外部执行器或使用自身有界操作能力。图形、图层、场景、时间轴和媒体生产由现成创意软件完成。

DESIGN-LAB 可以把 AAOS 知识和 WORK-LAB 实践转为图解、动画、交互演示、课件及其他学习内容，并参与反馈修订。教学生产是一类重要应用，不缩窄全品类定位；不接管 AAOS 的课程组织、长期学习状态或掌握评价。

品牌正式名称为 DESIGN-LAB。历史 OPEN-DESIGN 等名称保留在来源与兼容记录中，不用批量改写历史原件的方式改名。AAOS/ArcheAxis 的具体标识以该项目当前命名合同为准。

### 2 产品范围与必须分开的状态

长期范围包含品牌、平面、字体、出版、包装、空间、交互/UI、三维、动效、视频、声音与游戏视觉。每一领域分别声明知识、分析、提示词、执行、原生交付的实际覆盖；不让首个海报案例变成永久产品范围，也不把所有品类都做成导航和空模块。

允许自有设计专用规划、动作执行、观察、检查与恢复循环。复用 Python 服务、NativeWorkers、原生任务、已有适配、持久化和恢复，不另建通用 Agent 平台或平行运行时。不重造画布、渲染器、时间轴、模型网关、凭据系统或长期知识库。

不以项目管理看板、审批大厅、服务 KPI 和未来模块占位为首页中心。保留必要任务、集合、版本、预览、批注、暂停、取消和恢复；不删除底层项目表来追求词语一致。

### 4 从资料到能力再到产物

能力资产至少区分知识、可执行配方/适配器、参考/模板、结果/验证记录。联合目录不意味着都存同一物理位置。

分类用领域、场景、感知特征（构图、字体、色彩、材质、空间、运动、声音）、风格及混合关系、方法、目标结构、软件/版本/权限条件与实际支持范围等轴。既有七轴必须真实透传，不改名丢值。规范、方法、偏好、软件限制与法律/合同要求分开。

每个可调用能力说明解决问题、输入/输出、前提与不适用情况、知识版本、素材依赖、变量和强约束、软件实现、测试和反例、费用/权限、失效及撤回。优先复用 DomainPack/Method/Adapter/Quality 和 KnowledgeCandidate 等已有对象，不新增几十套同义 Schema。

吸收流程：发现 → 来源/版本/许可/用途 → 提炼方法与反例 → 绑定任务 → 中立适配 → 用例验证 → 能力分发 → 反馈更新。热度、星数、点赞、收藏用于发现优先级，不能作为审美质量、合法性或接入完成证明。保持审美/风格/类型等层级与多维分类，第三方技能作为未受信输入，不进入默认 Agent 规则发现目录。

优先吸收与当前任务缺口相关的少量来源。原包保留全部调研条目；Eagle、AYON、OpenAssetIO、GUI 桥、Figma、Adobe、Blender、AE、REAPER、ComfyUI 等仅按记录的用途取舍，不默认整套安装。SKOS/AAT/DTCG/OpenUSD/OpenTimelineIO 解决各自问题，不合并成万能无损格式。Qwen-Image-Layered 的 RGBA 分层不能冒充文本、矢量、智能对象或真实三维结构。

“精准提示词”按目标生成包交付：输入引用、结构/风格参考、局部遮罩、正文、真实支持参数、必须保持/允许变化条件、输出约定与检查。准确文案优先原生排版，锁位置优先结构对象操作；生成路线无法强约束时标明损失。原创需求可以从方法与多参考形成不同方向，不只机械复刻。

### 5 自动化与验证

按具体操作选择原生 API/脚本/CLI/官方写入、语义控件、有限视觉 GUI、混合路线或提示词/人工交接。原生接口通常适合已验证重复操作，但软件版本、功能损失和启动条件决定实际路线，不固定成绝对排序。

扩展现有 Adapter manifest、Observe、Plan、Execute、Verify、Recover：软件版本、文档身份、结构化动作、前后条件、受影响对象、读回、补偿和接管可核对。模型推理不自动获得软件权限，动作返回成功不自动证明内容正确。

同一 Windows 桌面、宿主实例、文档建立跨进程占用/租约与所有者；原生 API 和 GUI 也可能争用同一文档。超时先对账，再决定重试；幂等键绑定输入，同键不同内容冲突。禁止重复创建、重复导出或重复支付。暂停、取消、重启对账与预算截止返回可继续材料。

截图用于视觉核对，结构读回用于原生真实性，真人审美结论另记。PNG 不冒充 PSD，位图容器不冒充全矢量，成片不冒充时间轴工程；用户只要 PNG 时不强加 PSD 验收。截图反推未知原结构和被遮挡内容须明确为推断。

Human Jury 工程先接通，真人对版本作真实决定；Agent 可准备对象、差分与候选意见，不代签姓名、时间、接受结果。修改后不能沿用旧版本通过状态。低风险已授权分类与可回滚工程工作继续推进，不把全部剩余工作推给 owner。

### 6 AAOS 和 WORK-LAB 的归属

AAOS：长期原件/知识正文、来源、关系、版本、研究和 Human–AI 学习；课程登记、知识关联、练习、学习状态与评价。

DESIGN-LAB：设计语义、知识应用、专业判断、能力编译、宿主操作、结果核验；教学生产的表达设计、源工程、制作配方与修订。

WORK-LAB：编程、AI使用、自动化、治理实践，任务与真实执行证据，经验发现和技术复现；按需提供环境、权限、预算、并发与恢复支持。不是单纯调度器，也不是总控制器。Observer 保持只读，不能批准、执行或修改业务状态。

各自业务数据库和私有状态独立，通过公共合同交互；不合并三仓，不强制每次操作绕行 WORK-LAB。系统故障时独立可用并可本地恢复，不绑定共同发布节奏。

知识读取、候选提交和回执先跑通。AAOS 不可用时允许授权、版本固定、适合用途的只读快照；已知撤销、未知权利或要求新鲜检查的任务不能伪装通过。在途任务固定知识版本，更新用于新任务或明确重算。反馈待发队列必须先获准出域并幂等提交。

知识迁移是未来按批次执行的受控任务：旧 ID → AAOS ID/revision，原字节/来源/关系/权限/用途/哈希读回核对，一个知识写入主源，旧源只读，断网/冲突/撤销/恢复验收。制定方案不等于获准全库迁移；不默认移动客户、私人会话、凭证、大型工程和未知目录。

### 7 三方教学生产与学习反馈

共同链：学什么 → 前置知识 → 易误解点 → 例子 → 解释 → 学习者活动 → 判断理解。知识与技术正确性、表达质量和学习有效性分别验证。

| 学习目标 | 合适形式 |
|---|---|
| 相近概念辨析 | 对照图、层级、正反例 |
| 顺序与状态变化 | 分步演示、过程动画、可暂停时序 |
| 空间与结构 | 三维、剖面、分解 |
| 会操作但不会判断 | 分支情境、错误案例、选择反馈 |
| 看过仍不能独立完成 | 预测、复述、练习、新场景应用 |

不是所有知识都要动画。专业表达保留单位、条件、因果、时序；简化必须标记。动画播放不是交互仿真，仿真需参数、算法版本、初始条件和可验证结果。用现成软件/成熟组件；H5P 是候选，需承载实测才称兼容。

教学请求包含目标人群、前置知识、目标、知识/来源版本、重点/误解、形式约束和反馈目标。简单图解可省略无关字段。交付按需包含可展示内容、可修改源工程、文本、字幕与必要视觉描述、练习/反馈规则、知识映射、依赖和限制；制作时考虑无障碍。字幕与描述性文字稿不是同一份材料。

AAOS 登记课程、版本与学习状态；DESIGN-LAB 保留源工程和制作配方；以权限过滤的资产引用联合管理，不复制所有大工程。反馈关联知识版本、内容版本、场景/题目、观察及改进许可。

知识/技术问题回 AAOS 并由 WORK-LAB 等专业方验证；表达/教学问题回 DESIGN-LAB；运行/集成问题回实际模块，必要时 WORK-LAB 协助。联合问题可多方处理。同源文章、图解、视频、课件只有一条知识来源，不能互相引用冒充独立证据。播放完成≠掌握，Agent成功≠内容正确，没看懂≠知识错误。

首个联合案例采用《任务显示成功，为什么还不一定算完成？》作为可替换建议：WORK-LAB 提供获准的真实成功/失败/修复与复现；AAOS 组织知识、前置要求和练习；DESIGN-LAB 制作对照图、过程说明/动画与判断练习；AAOS 实际呈现并收集答案/解释/应用；反馈回正确负责人，形成一次可追踪修订。无实测材料标假设，不能三份报告代替闭环。

### 能力目录

不是来源登记表：一个能力对应可解决的问题，可有多个宿主实现。卡片先讲用途和示例，再讲能否分析、生成、操作及交付。来源、版本、权利、证据展开可查。

### 分析与制作

输入支持文字、截图、单文件、多图、音视频；输入分析深度分别注明。简单任务不先填完整项目。用户明确要分析、目标生成包、操作计划、最终媒体或原生工程；目标软件缺强约束则提供真实降级选择。

目标合同包含参考职责、编辑范围、精确文字、对象/相机/时间关系与输出规格。方向/DesignSystem可在需要时参与，不强迫每个短任务走完整Brief流程。已有方向绑定真实引用到native plan与产物，UI不把原始RIR/JSON交给普通用户补断点。

教学需求来自AAOS时自动带入知识版本、目标人群、目标、前置条件、易误解点、形式/反馈和验收，不复制教育后台。制作与普通设计共用图形、三维、动效、音视频能力。

### 成果与反馈

区分分析结果、目标生成包、执行结果、草稿/测试导出、可正式交付。每种按实际合同检查；下载ZIP不是合格交付。

支持版本比较、局部改稿、切换工具与继续执行。Jury可对确定版本Accept/Reject/Request changes并保存真实意见/回执；改稿后旧评审不自动沿用。

纠正可以仅本次有效、个人偏好或通用知识候选；显示是否允许回流及AAOS回执。教学反馈按知识/技术、表达/教学、运行/集成分别路由。用户可从本页专业修订，不需打开AAOS手工复制方法。

### 完整性检查

实际旅程：能力发现→输入→依据→方案/执行→读回与预览→修订/交付→反馈。要验证加载、空、未知、离线、错误、恢复、取消、无权限等状态，技术细节只在有助于决策时进入主流。

旧路由短期保留数据与兼容，明确退出条件。不能“新页只能看、生产还得回旧页”。浏览器测试保护业务行为、可访问性和数据边界；菜单数量和旧DOM不成为永恒规格。

### 3 权限与独立恢复

各项目只写自己业务域；知识正式writer由AAOS控制。Observer只读。教学代码与内容没有桌面执行权限；播放或互动中出现脚本/命令不能继承生产侧权限。

客户原件、Brief、私人会话、凭证和未授权资产不默认迁移；标题、摘要、缩略图、引用、向量索引、计数和去重也不能跨域泄露。知识保存与执行包资格分离，第三方文档/AGENTS/SKILL/安装命令不可授权运行。

独立模式用授权有限只读快照、任务恢复状态和已许可能力；不是第二知识主库。AAOS不可用时依据新鲜度/撤销/用途降级，需在线复核项不能伪装通过。获准反馈暂存，未获准内容不得放入待外发队列。三仓可按不同节奏发布，不把所有直接协作强制绕三方。

### 4 联合案例逐步验收

1. WL提供可复现、可授权真实材料；成功信号、失败、修复、环境和局限分别记。没有真实材料则内容标示例/假设。
2. AAOS生成版本化知识、来源、前置、目标及练习要求。
3. DL据学习目标选择图解/演示/动画/互动；专业简化保留语义并标注；提供文本、必要视觉描述、可修改源及依赖。
4. AAOS实际加载内容，呈现练习并记录回答/解释/应用；播放记录只表示行为，不表示掌握。
5. 至少一条实际反馈定位到知识/内容/题目，路由至正确责任方，修订并读回新版本。

本项目合同替身和可导入包只证明DL边界；三方实联与真实学习不在就标未完成。没有跨仓许可时提供接收文件与验证方法，不越仓代写。复用成熟组件需要运行承载实测，不能只写“兼容H5P”便通过。
