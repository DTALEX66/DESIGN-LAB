# Agent 执行入口

本任务是在既有 DESIGN-LAB 中实施 UI-20261009-r2。先读 `README.md` 与 `specs/01_UI_SCHEME.md`，以 R2 导航和页面规则为准；既有 22 项总任务维持一份台账。`specs/implementation_tasks.json` 是前端增量工作映射，不是新增业务系统。

先检查目标仓库 AGENTS.md、路由、UI 套件、品牌母版、现有七轴分类、DomainPack / Method / Adapter / Quality、任务/产物/版本/资格对象、读写接口与权限。登记真实字段和端点映射；`contracts/UI_DATA_CONTRACT.json` 是建议语义，不可冒充现存 API。`navigation.json` 的短 ID 仅用于本包原型，生产映射到现有稳定领域 ID。

实施要求：

- 三个主操作入口常驻；领域出现在能力资产的二级导航。音频、视频、动效、3D、平面、品牌独立可见。软件、风格、方法、场景、交付类型作为组合筛选，不扩大成三级导航。
- 一项能力/任务/产物保持一个身份，允许多个领域标签；切换领域不会复制记录或重置当前制作。
- 目录查看详情用抽屉；完整详情支持独立地址。选用能力携带确切资产引用与版本，目标与约束保留用户输入。
- 新建需求必须生成/选择正确任务身份；恢复草稿必须恢复同一身份。禁止用原型的单个 localStorage 演示对象代替生产任务存储。
- 当前包内 12 项能力、3 项成果和制作记录全部为样例；接真实服务时删除样例兜底，禁止查询失败后显示伪造的成功或已验证资格。
- 暂停、取消、恢复、下载、反馈提交按既有真实接口执行；timeout_uncertain 先核对状态再决定重试。UI 不补造宿主回执、知识 revision、真人意见或原生交付证明。
- AAOS 提供获准知识与学习状态；DL 管理设计判断、配方与制作；WORK-LAB 提供实践及技术证据。统一读取已有责任边界，不建立第二套知识/课程台账。
- 导航、按钮、表单、状态、文字、表格与计数全部实现成原生组件。插图直接用 SVG 或 PNG。不要截图整页再叠透明热区。
- 复用仓库获准品牌标识。`assets/brand/tri-project-brand-reference.png` 是保留的概念参考；CSS 裁切不等于正式矢量标识。不要据此另造 Logo。

顺序：先实现壳层、分类配置、组合筛选、抽屉和上下文；再接草稿/任务/产物接口及状态；最后完成键盘、响应式、主题、实际网络失败与生产资格验收。每阶段可以独立演示，但如实报告未接通环节。

交付：代码变更、实际接口/字段映射、领域/素材映射、关键状态截图、相关检查结果、真实未解决项。不要仅交一张概念图；不要把 UI 演示测试计入软件执行资格。
