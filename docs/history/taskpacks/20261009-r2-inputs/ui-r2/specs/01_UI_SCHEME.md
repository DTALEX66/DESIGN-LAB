# DESIGN-LAB UI R2 · 成熟可落地的方案

## 1. 方案决策

采用 **三个主操作入口 + 当前入口的二级导航 + 页面内组合筛选**。领域不是可有可无的隐藏标签：平面、品牌、3D、视频、音频等直接进入二级菜单。工作流程常驻，跨领域任务按同一身份延续。

R2 重点更新导航、分类检索、详情、任务上下文、成果查找与手机首屏。原有制作分析、计划、核验、评审、交付及反馈语义保留。DL 仍是专业设计能力与知识应用工作区，不转为项目管理看板。

## 2. 导航结构

| 常驻主入口 | 当前入口的二级导航 | 页面内容 |
|---|---|---|
| 能力资产 | 全部领域 + 11 个领域 | 全部资产 / 可调用能力 / 规范与方法 / 案例与参考 / 模板与配方 |
| 分析与制作 | 新建需求 / 制作记录与待继续 / 导入教学需求 | 输入与目标 → 分析与方案 → 制作与核验 → 成果与反馈 |
| 成果与反馈 | 全部成果 / 版本审阅 / 交付预检 / 反馈与候选 | 检索、版本、精确产物、正式交付与回流意见 |
| 连接与设置 | 辅助入口置底 | 实际连接、权限、环境与必要诊断 |

能力资产二级领域顺序：**平面设计、品牌与 VI、字体与出版、包装设计、3D 建模与渲染、空间与展示、动效设计、视频制作、音频与声音、UI 与交互、游戏视觉**。这是本次 UI 的初始配置，不是永久硬编码的“总共 11 类”。生产读取现有领域配置和稳定 ID，可扩展新领域并兼容旧引用。

音频与视频分别提供声音和画面工作入口；动效覆盖动作、节奏和时间关系，可与视频和 3D 关联。品牌是一种设计工作领域，可与平面、包装、三维和媒体制作交叉。教学表达作为场景筛选与需求导入，不把既有设计领域再复制一套。

同一资产可出现在多个领域结果里，但只有一份 ID/revision。结果计数为当前组合条件的去重记录数。当前领域的直接相关资产优先，跨领域关联随后展示；排序不会改变资产身份。领域没有资产时显示空结果，保留入口；不伪造能力，不因零条记录移除分类。

导航深度限定两级。参考 Carbon 的二级侧边导航及页内 tabs 建议，结合 DL 的领域切换频率，选择当前入口的上下文侧栏；这是本项目的设计判断，不是使用 Carbon 组件的要求。

参考：[Carbon UI shell left panel guidelines](https://www.carbondesignsystem.com/building-blocks/core/components/ui-shell-left-panel/guidelines)，核对日期 2026-10-09。

## 3. 桌面布局与手机布局

| 项目 | ≥1200 px | 768–1199 px | <768 px |
|---|---|---|---|
| 导航 | 256 px 侧栏 | 216 px 侧栏 | 底部 4 入口；页面内领域选择器 |
| 顶栏 | 64 px：面包屑、搜索、主题/环境 | 64 px：缩短搜索入口 | 60 px：当前位置、搜索、主题 |
| 内容边距 | 30 px | 22 px | 16 px |
| 卡片列数 | 3；≥1700 px 为 4 | 2 | 1 |
| 制作输入 | 左目标/约束，右交付/能力 | 单列 | 单列；目标先于附件 |
| 详情 | 右侧 450 px 抽屉 | 450 px 抽屉 | 全屏详情对话框 |
| 持续任务状态 | 页面底部任务条 | 同左 | 底部导航上方精简任务条 |

手机目录优先显示领域、搜索和第一张能力卡；交付范围等组合条件由“更多筛选”展开。领域选择一直可见，入口不会随主侧栏消失。底部导航保留连接入口；任务条只在实际存在当前任务/待继续任务时显示，退出/取消后按真实状态更新。原型任务条是明确标注的示例。

侧栏的主入口和辅助入口固定，上下文列表独立滚动。内容保留底部留白，确保最后一个按钮能滚动到任务条上方。全局浏览器横向溢出为零；宽表格在自身区域滚动。

## 4. 能力目录

从上到下：标题与主要操作、简短引导、资产类型 tabs、当前目录搜索、基础筛选、已选条件与结果数、卡片/列表。

- 基础筛选：交付类型、实际能力范围。更多筛选：场景、风格、设计方法、软件候选。
- 领域与资产类型区分：领域回答“做什么设计”；资产类型回答“用什么知识/能力”；软件回答“在哪个工具路线中制作”。
- 搜索匹配名称、目标、领域、方法、风格和软件候选。候选软件不等于已连接软件。
- 卡片显示示例图、资产类型、名称、用途、多领域标签、实际范围、详情操作。未知执行资格明确显示待核验。
- 同领域、同任务上下文下，清除筛选只清除检索条件；不会取消领域选择或删除任务。
- 生产支持排序和分页/虚拟列表；先按权限过滤，再统计和返回。筛选配置来自已有分类轴，避免新建重复字典。

R2 原型支持 12 项样例的领域、类型、输出、范围、场景、风格、方法和软件组合筛选，以及卡片/列表切换。没有已核验执行样例，所以“执行已核验”产生真实的空结果。

## 5. 详情与使用能力

点“查看详情”打开抽屉，保留目录领域、条件、位置和焦点。抽屉依次呈现用途、图例、领域、资产类型、能力范围、交付目标、候选路线和操作。完整详情有独立地址，可以被重新找到。

生产详情还须读取准确 revision、来源、授权、适用/不适用条件、输入要求、知识引用与执行资格。方法、参考和配方沿用各自真实对象语义，不能给所有类型都套一个已验证的“可调用能力”结论。

“用于本次制作”携带确切引用进入任务工作区。生产区分新建任务与续写已有任务；已有任务不能被浏览另一张能力卡悄悄替换。多个能力关联可以作为任务的引用集合，资产的适用领域不必全部强加为任务领域。原型仅演示选用一项资产和编辑领域上下文。

## 6. 分析与制作

页面顶层展示任务标题/状态、所属领域及当前选用能力；流程分四步，步骤可以回看已经确认内容。输入区使用以下信息分组：

| 分组 | 内容 | 行为 |
|---|---|---|
| 目标与输入 | 需求、文字、多模态素材 | 描述可先填；素材支持范围读真实环境 |
| 参考职责与约束 | 内容/结构/风格/节奏、强约束、偏好、允许修改范围 | 强约束与偏好分别保存 |
| 交付目标 | 分析、目标包、原生工程、最终媒体；工具及格式/尺寸/时长 | 根据实际资格提示可用路线 |
| 能力与知识 | 资产 revision、获准知识 revision、教学需要 | 保持来源与版本，不复制 AAOS 台账 |

跨领域示例：“品牌三维广告片”同时属于品牌、3D、视频；声音部分可再关联音频。只保存一个任务，镜头、材质、剪辑、配音可由不同能力完成。任务领域可调整，不清空用户描述、约束与交付目标。

草稿变更自动保存到正确任务身份，并显示正在保存/已保存/保存失败。未保存变更离开时给出恢复机会。环境不支持文件持久保存时明确要求重新选择，不能只保存文件名就声称原文件已恢复。

原型验证了表单多字段、领域编辑、主题切换、导航返回和浏览器刷新时的本地草稿保留。生产应接现有草稿和任务持久化接口。原型新输入不会驱动真实分析；后续制作步骤继承 R1 品牌海报示例，上方按钮明确写“查看品牌演示流程”。

## 7. 制作记录与持续状态

“制作记录与待继续”是找回工作的入口，显示任务、领域标签、真实状态、最近确认点与继续操作。进入任务后恢复同一任务身份、约束、计划、输入引用和版本；发生失联先核对当前宿主/文档和动作回执，再恢复操作。

页面底部持续任务条显示当前任务与真实状态，并支持返回该任务。跨目录浏览仍保留它，但任务条不应默认冒出不存在的任务。耗时操作有可查询状态；暂停和取消不是单纯改按钮文字。

原型有三条制作记录供布局示意；其状态不代表真实排队或运行。生产按既有任务接口提供进行中、待继续、已结束等筛选。

## 8. 成果与反馈

成果按交付身份与版本组织，通过领域、交付类型和名称/版本检索。卡片明确是方案、草稿、目标包、最终媒体还是原生工程。同一个跨领域成果只维护一个身份。

详情显示确切产物版本、可显示的预览、实际文件/工程引用、检查结论、真人意见与局部改稿。创建新版本后，旧版评审意见不能自动升级为新版通过。

交付预检读实际文件与资格：格式、来源、引用完整性、原生可编辑性、声画技术规格等按产物类型检查。允许用户先下载方案草稿或目标包，但不能写成已经完成正式原生工程交付。

反馈回流允许选择本次任务、案例/方法候选等范围。保留来源、同意范围与受理回执；AAOS 更新知识、WORK-LAB 提供技术证据按已确认边界办理。

## 9. 全局搜索

顶部按钮及 Ctrl/Cmd+K 打开搜索。搜索范围分能力资产、制作记录、成果；显示对象类型和去向。选择后进入正确对象，Esc 关闭并返回原触发入口。生产搜索以用户权限和已有搜索接口为准，禁止泄露无权对象标题或计数。

原型对本包样例演示三个对象组，没有远程检索。目录内搜索始终限制当前筛选范围，与全局搜索职责明确。

## 10. 状态、错误与资格

| 状态 | 用户看见什么 | 必须遵守的行为 |
|---|---|---|
| loading | 骨架与等待说明 | 保留结构，不先显示成功 |
| empty | 条件、原因与调整入口 | 保留领域和输入 |
| unknown | 未知/待核验 | 缺少证据不能推断通过 |
| offline / error | 获取失败、可重试 | 不用样例覆盖真实失败 |
| forbidden | 权限原因与可用路径 | 不显示敏感记录 |
| timeout_uncertain | 操作状态尚未确定 | 先查回执/状态，避免重复写入 |
| conflict | 哪个版本已改变 | 读回、对比、选择处理后再写入 |
| queued / cancelled | 真实排队/取消状态 | 保留已确认节点和已存在产物 |

分析、目标包生成、真实执行、原生工程交付、真人评审是不同结论。没有输入、产物、宿主或受理证据的 null/unknown 字段不得转换为成功。

## 11. 视觉与组件

沿用冷蓝、银白、深海军蓝体系，深色适合工作区；提供浅色主题。减少装饰性超大 Hero，用内容缩略图帮助识别。状态色只表达状态，避免大量成功绿或霓虹。

采用 14 px 正文、12–13 px 辅助内容、桌面 27 px/手机 22–23 px 标题；1 px 边框、7 px 控件圆角、10 px 卡片圆角；4/8/12/16/24/32 的间距基线。控制高度以 40–44 px 为主，手机主要操作至少 44 px。

组件拆分：AppShell、PrimaryNav、ContextNav、DomainSelector、GlobalSearch、AssetTypeTabs、FacetFilters、ActiveFilterBar、CapabilityCard/ListRow、AssetDrawer、TaskContext、BriefForm、DeliveryTarget、StepNavigation、ActivityDock、TaskRecordList、ResultCard、EvidenceSummary、VersionReview、DeliveryPreflight、FeedbackForm、ConnectionStatus、Empty/ErrorState。

生产完成焦点可见、对话框焦点限制与返回、标签与表单关联、错误说明、减少动画、键盘操作及实际主题对比度检查。当前包不宣称通过完整 WCAG 审计。

## 12. 素材与切片

`assets/art/` 共 14 张独立矢量示例，各有 SVG 960 × 600 和 PNG 3840 × 2400。新增：three-study、video-study、audio-study、game-study。其余 10 张保持 R1 可复用资产。插图是示例，不能当作实际三维工程、时间轴工程、声音文件或最终客户产物。

媒体可使用独立图源；文本、导航、按钮、标签、搜索、表单、表格和状态实现成组件。避免从整页截图裁下低清卡片再放大。SVG 可无损放大；需要裁切 UI 效果图时按 `screen_map.json` 和 `slice_map.json` 的 CSS 坐标与 deviceScaleFactor 转换。

4K 首屏实际为 3840 × 2160，CSS 视口 1920 × 1080、倍率 2；新增单素材 PNG 实际为 3840 × 2400。完整长页与首屏单独命名，不混用坐标。新版效果图、原型和配置须保持对应。

## 13. 实施顺序与验收

P0：壳层/分类/目录/抽屉/制作上下文与响应式；P1：真实检索、草稿、任务、产物、知识版本和资格接口；P2：真实状态/恢复/交付、键盘与主题、领域素材覆盖和性能。映射回既有 DL-FINAL 任务台账，不创建第二套任务账。

前端验收至少覆盖：11 个领域入口、跨领域去重、组合筛选、零结果、详情返回、手机领域选择、准确对象搜索、新建与恢复区分、多字段草稿保留、无全页横向溢出、任务条正确状态、真实权限/错误/不确定超时及精确版本评审。

已完成本包浏览器检查：91 项通过，覆盖 390/768/1366/1920 px、17 条页面路线；脚本错误、404 与外部请求为零。检查明细在 `evidence/verification.json`。这些结果仅证明参考 UI 相应交互可用，未证明真实服务、软件或交付链路可用。
