# DESIGN-LAB 多模态创作与可编辑重建：后续执行任务方案

版本：2026-09-05 / 本轮需求整合版

性质：产品与实施方案。基于本对话可见需求，以及本轮官网、官方文档、上游仓库和公开测试记录核查。本轮没有重审 DESIGN-LAB 最新提交，没有在用户电脑安装或实测 Adobe、模型和桥接；文中阶段均为待实施目标，不是已有功能声明。本文件新增并保留此前归档，不宣称全部历史原件已重新核对。

## 1. 产品决定与原始诉求

DESIGN-LAB 定位为本地优先、有可视化前端的多模态创作与可编辑重建工作台。输入可以是图片、作品集、网页参考、音频、视频、生成图片或设计工程；输出可以是可编辑平面工程、三维场景、音频素材与分轨、剪辑工程和最终作品。

首先满足：一张参考海报/合成图 → 在 Illustrator 与 Photoshop 中重建 → 对比修正 → 交付能重新打开、改字、改色、换图的 AI/PSD 工程。必须同时覆盖 AI 和 PS，第一版有真实前端。音视频生成从基础架构和首版试用入口纳入，随后交付完整的配音、配乐、视频和剪辑闭环。三维是完整产品范围，按阶段落地。

用户用途：个人研究、非商业。H3 本地运行要求保留。软件和模型仍分别记录其来源、许可证、使用范围；不将第三方内容统一改标成个人非商业许可证。

产品提供三种任务模式：

- 忠实重建：固定参考、文字、比例、结构和重点对象；对缺失信息作显式标记。以视觉接近度和编辑能力为验收依据。
- 新内容生成：根据文本、参考、分镜生成图像、语音、音乐和视频，保留版本和生成参数。
- 工程制作：把已有或新生成的素材组装为 AI/PSD/BLEND/PRPROJ 等原生工程，并支持局部修改。

模式必须显式记录，不能把复刻任务悄悄改成自由创作。不能把整张参考图作为底图放进 PSD 就声称已分层重建；不能把视频导入剪辑软件就声称恢复了原始镜头、特效与时间线。

## 2. 前期软件收敛

收敛目标是减少重复职责、常驻进程、独立项目库和用户操作界面，而非强迫所有专业工作由一个软件完成。已安装软件无需删除；没有进入默认链路的软件不自动启动。

| 层次 | 默认选择 | 启用条件与职责 |
| --- | --- | --- |
| 用户入口 | DESIGN-LAB 前端 | 项目、参考、对象/镜头、任务、预览、版本、交付 |
| 默认 Agent | Codex | 通过官方支持接口接入；承担规划、工具调用和结果修正 |
| 可选 Agent | Hermes / DSH | 共用工具入口；每个任务只选择一个主执行器；不作为首版必装项 |
| 生成工作流 | 一套受管理的 ComfyUI | 图像、视频及有可靠节点的音频工作流；默认通过 API 调用 |
| 图像模型 | 按案例选一个默认模型 | Stable Diffusion 是模型家族；如果用户说的是 A1111/Forge 等 WebUI，作为已有环境兼容选项，不再默认搭第二套生成服务 |
| 平面工程 | Illustrator + Photoshop | 第一交付阶段均需可操作 |
| 音视频工程 | Premiere Pro | 音视频闭环阶段启用；先覆盖剪辑、字幕、独立音轨和输出 |
| 三维工程 | Blender | 空间和三维案例启用；先选一个三维宿主，避免同期接入 C4D/3ds Max/Maya 全部产品 |
| 后台媒体工具 | FFmpeg / ffprobe | 代理预览、格式处理、媒体信息与交付校验，不增设面向用户的独立工作台 |
| 补充创作软件 | OpenDesign / MiniMax Design 桌面客户端 | 按任务启用；保持独立身份，输入输出纳入 DESIGN-LAB 项目 |
| 后续 Adobe 能力 | After Effects / Audition / InDesign / Substance 等 | 分别在复杂动效、精细声音修复、长文档排版、专业材质需求出现时接入 |

ComfyUI 官方提供 REST/WebSocket API，可提交工作流、获取输出、监视进度，无需打开节点界面。[官方服务接口](https://docs.comfy.org/development/comfyui-server/comms_overview)

“一个生成入口”不等于把所有模型硬塞进同一个 Python 环境。缺乏可靠 ComfyUI 节点的语音/音乐模型可作为独立服务，通过相同任务协议访问；依赖隔离、模型文件尽量复用，GPU 由统一队列调度。

## 3. OpenDesign 与 MiniMax Design 的独立角色

### OpenDesign

作为现成设计工作台与模块供体，重点评估项目界面、预览、设计技能、Agent 适配。公开仓库提供 Codex/Hermes 接入及 DSH 原生运行适配，主要展示 HTML/PDF/PPTX/MP4 等产物。是否可作为整个前端底座，需要通过 Adobe 原生对象预览与局部修正案例决定，不直接由 README 下结论。[仓库](https://github.com/nexu-io/open-design)

首轮比较两种实现：扩展其已有工作台，或复用适配/界面模块组成 DESIGN-LAB 专用工作区。只做一个可运行的代表性切片比较；选定后只保留一条主前端路线，不维护两套默认入口。

### MiniMax Design 完整桌面软件

用户指定的是有官网、有 Windows/macOS 客户端的 MiniMax Design。将它列为“外部创作应用”适配对象，不用 ComfyUI 插件或 Mini-Agent 代替它。官网介绍多模态创作、技能与插件、本地素材及专业工具衔接。[官网](https://design.minimax.io/)

接入按三档实施：

1. 文件协作：从 DESIGN-LAB 交出参考与任务说明，打开该软件；用户在其中创作并导出，DESIGN-LAB 接收结果、建立素材版本。最初允许明确标记的人工步骤。
2. 文档化接口：核实客户端是否公开插件、CLI、MCP、深链或项目接口；只对实际发现且验证的能力做自动接入。
3. 桌面操作补充：无接口但有稳定可见操作时，评估带状态检查的 GUI 自动化；失败可接管，不声明后台无交互完成。

MiniMax 开放平台 API/CLI 是另一个适配对象：能调用模型不等于能控制 MiniMax Design 客户端，不假定账号权益互通。官方 API/CLI 可用性仍以实际版本和账户为准。[官方 CLI](https://platform.minimax.io/docs/token-plan/minimax-cli)

## 4. 用户全流程与前端

新建项目 → 导入参考/文案/素材 → 选择重建、生成或制作 → 设定交付格式与可编辑要求 → 查看对象/镜头/声音拆解 → 执行任务 → 预览对比/试听 → 局部修订 → 原生工程验证 → 交付与方法沉淀。

前端首版必须包括：

- 项目与素材：原始参考、来源、图片/音频/视频缩略预览、工程文件、版本。
- 创作工作区：参考与结果、对象列表、文字批注、图片叠加对比；音视频可播放、试听和定位时间片段。
- 任务面板：当前软件/模型、步骤、进度、等待原因、取消、重试、打开宿主与人工接管。
- 交付：原生工程、素材依赖、导出文件、生成工作流与运行记录。
- 简洁设置：软件连接、本地模型状态、执行位置、目录、预算/超时；模型细节放高级设置。

不在首版开发完整 PSD 画布编辑器、Blender 建模视窗或 Premiere 专业时间线。前端支持对象选择和镜头顺序/时长的轻量调整，精细编辑交给宿主。点击打开后可直接进入对应文件，接管结束后重新读取宿主状态，不覆盖人工改动。

## 5. 同一项目跨媒体流转的例子

参考文化墙图片 → 重建 AI 展板和 PSD 素材 → Blender 建立墙体与立体字、材质、灯光 → 输出相机画面 → 生成若干视频镜头 → 生成讲解配音和背景音乐 → Premiere 组装字幕与独立音轨 → 导出视频，同时保留源工程。

这是完整产品的目标链路，不要求用户每次跑完全部步骤。只研究平面时，到 AI/PSD 即交付；只生成配音时，只跑声音支线。

每项资产有稳定标识、文件版本和依赖：标题改动先更新其 AI 对象，再把使用该标题的渲染/镜头标为待更新。默认只重跑受影响步骤，锁定用户确认过的区域和版本。

## 6. 生成、复刻与可编辑性的边界

| 媒体 | 可交付的编辑能力 | 不能混淆的边界 |
| --- | --- | --- |
| 平面 | 文本框、简洁路径、图层、蒙版、智能对象 | RGBA 分层并不自动获得可编辑字体与几何路径 |
| 三维 | 独立对象、尺寸、材质、灯光、相机 | 单视角外观拟合不等于恢复隐藏结构与真实尺寸 |
| 配音 | 按句音频、文稿、字幕时间、语速与生成参数 | 波形编辑不等于原始发音生成状态可无损逆推 |
| 音乐 | 音频版本、可获得的独立声部、工程轨道 | 分离声部不等于原始 MIDI、乐器预设和编曲工程 |
| 视频 | 分镜、独立片段、字幕、旁白/音乐轨道、剪辑工程 | 生成视频中的每个物体不自动具备三维/矢量编辑能力 |

语音首选验证 Qwen3-TTS；音乐首选验证 ACE-Step 1.5 的适当变体，只保留各一个默认候选。二者是能力模块，不增加用户必须操作的独立界面。不要将 ACE-Step 所有变体都视为具有相同的分轨/续写能力。[Qwen3-TTS](https://github.com/QwenLM/Qwen3-TTS)、[ACE-Step](https://github.com/ace-step/ACE-Step-1.5)

Premiere 采用官方 UXP 接口优先，接口覆盖不到的操作列出缺口后再选择桥接或人工接管。[Premiere UXP](https://developer.adobe.com/premiere-pro/uxp/)

## 7. H3 本地部署必须单独验收

保留 H3 本地运行目标，不以 MiniMax Design 的桌面安装完成代替模型运行完成。官方说明 H3-Context-IR 的多阶段托管流程未包含在开源发布中，因此需区分：

- 本地 H3-Base 推理是否实际运行；
- 上下文处理、编码和后处理各自在哪里运行；
- 是否借用了远程服务；
- 所用配置、时长/分辨率、设备、峰值显存和总耗时。

严格本地模式下不能静默调用托管 Context-IR 或云端生成，缺少步骤应显示原因。优先验证官方允许的本地输入流程或自行实现的预处理，并标明与官方托管流程的差别。硬件不够时保留阻塞状态和可执行的资源方案，不伪造成功，也不阻止 AI/PS 和独立音频流程使用。[H3 官方说明](https://github.com/MiniMax-AI/MiniMax-H3)

## 8. 内部架构与运行规则

采用四层：前端工作区；项目与任务服务；可替换 Agent/生成/宿主适配器；原生软件与模型。DESIGN-LAB 负责业务任务和工程状态，现有 Agent 负责推理与工具调用。

语言建议：TypeScript 负责前端和必要的 Agent/Adobe 桥接；Python 负责图像/音视频分析、任务服务和模型适配。保留成熟模块的原生语言，不为统一语言重写可用桥接；第一闭环不依赖 Rust/C# 全量迁移。若复用既有前端底座，应沿用其可维护技术栈，避免先做框架迁移。

数据记录以最小集合起步：Project、AssetVersion、Job/Attempt、Operation、Artifact、CapabilityEvidence。每条证据包含软件/模型版本、配置、执行位置、输出文件及校验；ID 不可空，状态枚举与实际读写一致。Job 与尝试次数分离，重试不能把已经成功创建的图层重复创建。

同一文档同一时刻一个写入者；用户接管时暂停自动修改。重任务按 GPU 资源排队，不默认让 H3、图像模型、音乐模型和 Blender 同时争抢显存。取消行为标明是停止排队、请求中断还是等待当前不可中断操作完成，不能显示“已取消”却继续写文件。

项目资料、任务和工程以 DESIGN-LAB 为准。给不同 Agent 提供生成的技能/说明和工具接口，不依赖任何一个 Agent 的私有记忆作为唯一历史。软件本身要求的插件安装位置如实记录；项目资产和缓存保持在项目配置目录，不承诺宿主软件所有系统写入都能重定位。

## 9. 任务列表与验收门槛

以下 18 项为新的交付队列，不按任务数估算完成百分比。每项必须提交可审查产物；只有目标环境实测并附结果，才可标记“已验证”。

### 阶段 A：恢复可信基线，选定复用组件

**T01｜当前仓库与历史对照**

- 核对执行时的 main/工作分支/PR SHA、原任务包和归档索引；将旧任务标为保留、吸收、替代、暂缓，保留原 ID。
- 针对此前指出的 CI/许可证状态枚举、schema 引用与字段、依赖锁定、证据脚本执行路径逐项复现；已修复项附当前证据，不重复实现。
- 验收：来源与文件存在性清单、SHA、旧新任务映射、当前可复现阻塞项。哈希清单不能替代原件存在性证明。

**T02｜Windows 软件与模型能力盘点**（依赖 T01 的工作目录确定）

- 探测 Adobe/Blender/ComfyUI/Agent 版本、GPU/显存/磁盘、模型路径和可启动性。
- 区分发现、可连接、可读取、可修改、可导出、已重开验证，不用单一绿灯表示全功能可用。
- 验收：机器报告与缺口；H3 本地可行性有实际参数依据。

**T03｜AI/PS 控制组件对比**（依赖 T02）

- 比较 Illustrator 官方 MCP、adb-mcp 和 Photoshop MCP；正式版 AI 必要时测试 ie3jp 方案。
- 用同一案例验证新建、文本、路径/图层、蒙版、预览、保存、重开、错误返回与取消。
- 验收：每个宿主选定一条默认路径；关键缺口明确。社区文档的 macOS 通过结果不能替代 Windows 实测。

**T04｜前端与 Agent 最小复用切片**（依赖 T02；可与 T03 独立推进）

- 默认接 Codex 官方支持接口，研究 OpenDesign 项目区和适配器的可复用性。
- 做出“选参考→触发一个真实操作→显示进度→显示产物→打开工程”的可运行切片。
- 验收：选定一条前端方案；保留一个默认执行器，Hermes/DSH 留适配接口。

### 阶段 B：首次可用版本，AI/PS 完整案例与媒体入口

**T05｜项目资产与任务服务**（依赖 T01、T04）

- 实现资产版本、任务尝试、状态、文件依赖、同文档写入控制与取消；把“未实现”正确显示。
- 验收：重启后能恢复记录；重复提交不重复破坏工程；错误不被标为完成。

**T06｜平面拆解与对象映射**（依赖 T05）

- 识别文字、规则图形、图像和遮挡；为对象关联 AI/PS 对象标识；允许用户纠正与锁定。
- 分层、OCR、描摹作为可替换模块，先支持代表案例所需能力；缺字/字体替代可见。
- 验收：标题为可编辑文字，关键图形为合理路径，图像层有独立蒙版，未恢复区域有标记。

**T07｜AI/PS 真实工程制作**（依赖 T03、T06）

- 在两款软件中生成混合海报工程，正确交换图片/矢量素材并保存依赖。
- 读回尺寸、对象、图层和导出状态；保留用户的人工修改。
- 验收：AI 和 PSD 均能关闭后重开；分别完成改字、改色、换图，重新输出成功。

**T08｜对比与局部修正**（依赖 T07）

- 实现对齐、叠加、区域批注；将问题定位到对象，只修订相关步骤。
- 验收：修改一次标题和一次人物位置，不重建已锁定区域；保留前后版本与导出证据。

**T09｜统一生成入口与 ComfyUI 适配**（依赖 T05）

- 实现提交、进度、失败、取消、产物回收；工作流固定模型/节点版本，缓存命中不能计作新生成成功。
- 首版至少有一个实际图像生成流程；音频和视频生成使用相同任务界面，未就绪能力明确显示。
- 验收：输出真实可预览媒体及工作流记录；本地和远程执行位置明确，敏感资产不因自动回退而外发。

**T10｜音频首条生成闭环**（依赖 T09）

- 先接一个配音方案，生成中文段落、支持逐句重做、输出 WAV 与文稿；模型可走独立服务。
- 验收：可以试听、下载和导入 Premiere；文字无漏句，时长有效，局部重做不覆盖其他句子。

阶段 B 的首个平面交付门槛：T05—T09 的平面链路通过。T10 为紧接着交付的音频切片，不能把整个音视频范围无限期延期；音频可独立使用，不必等待三维。

### 阶段 C：音视频完整制作

**T11｜音乐生成与音轨管理**（依赖 T09、T10）

- 验证 ACE-Step 适当变体或一个已可用的生成服务；声音拆为旁白、音乐、音效等资产角色。
- 验收：生成真实配乐，试听与替换有效；标注是原生成独立轨还是后分离声部；不声称获得 MIDI 原工程。

**T12｜H3 本地与视频生成**（依赖 T02、T09）

- 先用低成本参数完成一次真正 H3 本地推理，再递增分辨率/时长；每次记录设备、耗时和资源。
- 分镜、参考、输入参数、执行位置与输出关联；视频中关键文字优先在剪辑阶段用原生字幕/图形叠加。
- 验收：本地运行证据完整；隐含远程步骤可见。硬件阻塞时明确保留，允许其他明确选择的生成方案继续交付，不冒充 H3 成功。

**T13｜Premiere 工程闭环**（依赖 T10、T11，以及 T12 或其他已验证的视频生成路径）

- 导入镜头、旁白、音乐和字幕，建立时间线，调整时长/音量并导出。
- 用官方 UXP 与已验证桥接生成真正 PRPROJ；中间时间线格式只能用于传递，不代替原生工程验收。
- 验收：15—30 秒示例有至少两个生成镜头、独立旁白/音乐轨、可改字幕；更换一个镜头后重新导出；工程重开无丢失素材。

**T14｜OpenDesign / MiniMax Design 软件协作**（依赖 T05、T09）

- 两个软件分别建立连接能力记录；OpenDesign 测试公开接口，MiniMax Design 从文件交出/回收开始验证。
- 记录自动、辅助、手动三类步骤；未确认客户端 API 时不伪造自动控制。
- 验收：从工作台交出任务，在指定软件产出至少一项素材并回收到正确项目；记录来源和版本。任一软件不可用不阻断已有平面/媒体链路。

### 阶段 D：三维和跨媒体闭环

**T15｜Blender 参考重建**（依赖 T05、T09；无需等待全部阶段 C）

- 复用 Blender MCP/Python，先相机匹配与主要体块，再材质灯光；保持空间结构可编辑。
- 验收：一个展墙或小展台有独立物体、材质、相机与灯光；BLEND 重开后改尺寸/颜色再渲染；推断区域明确。

**T16｜跨媒体依赖更新**（依赖 T07、T13、T15）

- 关联平面展板、三维贴图/几何、渲染画面、视频镜头和声音资产。
- 验收：替换一个 AI 标题或展板图，只更新受影响工程和镜头；保留已确认旁白、音乐与其他镜头。

**T17｜启动、便携与交付质量**（依赖每个阶段的已验证链路，分批实施）

- 桌面入口启动服务与前端，默认不弹出多余终端；只启动所需组件；项目移动后支持重新定位素材与模型目录。
- ffprobe 检查媒体参数，人工播放检查口型/声音/画面语义；原生宿主重开检查编辑能力。
- 验收：重启后能继续任务；取消与失败恢复通过；交付工程、素材与最终输出完整。已安装 Adobe 的系统依赖如实列出，不声称全部软件可脱离安装随盘运行。

**T18｜历史归档、仓库规范与渐进迁移**（从 T01 开始，伴随每次交付）

- 更新 AGENTS、安装说明、能力矩阵、唯一任务台账；保留原始历史和新旧任务映射。
- 源码、测试、文档、schema、工作流有稳定位置；密钥、模型、大媒体、缓存和用户工程不混入普通源码提交。
- 锁定依赖与 CI 安装方式一致；schema 测试覆盖真实无效输入；文档的支持范围与实测一致。
- 旧模块先检查消费者、迁移调用并验证，再删除无用副本；历史归档不能因“清理仓库”丢失。
- 验收：同一功能没有两个默认实现/任务台账；已完成状态均可追溯到产物或目标机器证据；CI 通过但未跑宿主测试的项目仍标“待实机”。

## 10. 验收样例与排序

| 样例 | 第一关注点 | 最终证据 |
| --- | --- | --- |
| 含标题、曲线图标和照片的海报/文化墙平面 | 视觉贴近、中文文字与矢量可改、照片蒙版完整 | AI、PSD、预览、重开与编辑后输出 |
| 中文讲解音频与短视频 | 真正生成、可逐句重做、旁白与音乐独立、字幕正确 | WAV、字幕、独立片段、PRPROJ、最终 MP4 |
| 展墙/展台参考 | 相机、比例、物体结构、材质灯光 | BLEND、引用素材、原视角渲染、修改后渲染 |
| 平面改动联动视频 | 只更新相关对象和镜头 | 依赖记录、前后版本、局部重跑日志 |

每项比较安装成本、目标系统成功率、人工修正时间、视觉/听觉质量、可编辑程度、恢复能力、硬件/调用成本。先得到一组代表案例基线再设数值阈值，不编造通用“99% 相似度”。关键文字、文件存在、独立对象与重新打开属于明确的通过/不通过条件。

## 11. 给执行 Agent 的启动指令

从 T01 开始核对当前仓库与本方案，不先重写全仓、不先安装整个 Adobe 家族、不先扩张模型列表。依据当前提交复现此前问题，已有修复只补证据。T02—T04 选择经过实机测试的组件，随后优先交付 T05—T10，让前端、AI、PS 和首条音频生成可用。遇到硬件或未公开接口，保留明确阻塞项，同时推进不依赖它的任务。

开发时使用可复用上游实现，保留来源/许可证与固定版本。所有“支持”“完成”“全本地”声明必须对应实际能力和证据。每次交付说明用户现在能做什么、仍有哪些人工步骤和未完成范围。
