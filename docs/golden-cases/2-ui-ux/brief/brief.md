# Golden Case 2: UI/UX — ProcureFlow Dashboard

## Brief

**Project**: ProcureFlow — SaaS Procurement Dashboard Redesign
**Domain**: B2B SaaS / Enterprise Analytics
**Budget**: $30,000–$45,000
**Timeline**: 8 weeks

### Background
ProcureFlow's legacy dashboard has 43% user drop-off in the first week. The redesign must reduce cognitive load while surfacing actionable insights for procurement teams managing $50M+ annual spend.

### Target Audience
- Primary: Procurement analysts (daily users, 4+ hrs/day)
- Secondary: Category managers (weekly reviews)
- Tertiary: C-suite (monthly executive summaries)
- Demographics: 28–50, Excel-native, skeptical of "pretty" interfaces

### Design Challenges
1. **Data density**: Show 200+ SKUs without overwhelming
2. **Actionability**: Surface anomalies before user searches
3. **Accessibility**: WCAG 2.1 AA compliance mandatory
4. **Performance**: Must render <2s on 3G connections
5. **Customization**: Users must save personal views

### Deliverables
1. User research synthesis (interviews, survey, analytics audit)
2. Information architecture diagram
3. User flow maps (5 core workflows)
4. Wireframes (low-fi, all key screens)
5. High-fidelity mockups (desktop, tablet, mobile)
6. Interactive prototype (Figma, clickable)
7. Design system components (80+ components)
8. Accessibility audit report
9. Handoff documentation (Zeplin/Figma dev mode)
10. Usability test plan + results

### Constraints
- Must integrate with existing React component library
- Must support RTL languages (Arabic, Hebrew)
- Must work at 1280px–3840px viewport widths
- Must comply with SOC 2 data handling requirements
- Must include keyboard navigation for all interactions

### Success Metrics
- Task completion rate: >90% (baseline: 67%)
- Time-on-task: -40% for core workflows
- System Usability Scale (SUS): >80
- Accessibility: Zero critical/serious issues
- User satisfaction: >4.2/5.0
