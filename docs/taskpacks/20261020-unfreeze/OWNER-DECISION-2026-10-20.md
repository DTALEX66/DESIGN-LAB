## 效力与解释

1. **定点解冻（产品实施）**。`DL-TP-20261019-DIRECTION-R1` 的"本轮不实施产品功能"是对**规划轮**的约束，
   现由 owner 直接指令在且仅在以下三段产品实施上被取代：
   - **Prompt Intelligence 入口**：把提示词生成与反推做成可调用入口（服务 façade + CLI + 路由 + 工作台面板）。
   - **候选导出出口**：`export_payload` / `to_v1_projection` 目前**在 `src/` 内零调用者**，本决定授权把它接到真实调用方，
     使"导出"成为可寻址动作而不是本地合同自检的一个布尔字段。
   - **模型选择接口**：模型不做锁定；做菜单导航 + 接口，由**用户自行选择本地或云端模型**。
     `currentExecution` 其余 34 项仍 `FROZEN_DEFERRED`，release / 安装态分发 / 真实宿主 E3 / 真人 E4 /
     ComfyUI 与 H3 验收继续冻结；解冻仍需 owner 新的明确授权。
2. **模型选择的读法（关键，防两侧误读）**。"不锁死"取消的是**把用户挡在选择之外**，不是取消 fail-closed 的
   **默认值**：`AGENTS.md` 关于 `UNQUALIFIED_*` 默认 `defaultEnabled: false`、零 checksum / 许可冲突 / 模型缺失 /
   硬件不足时 resolver 必须 fail closed 的规则不变。用户的显式选择是一次**被记录的用户动作**，
   它不改变模型的合格状态、不把 `UNKNOWN` 改写为合格、不宣称推理已验证；云端选项必须写明**哪些数据离开本机**。
   因此选择面呈现的是"可选 + 现状 + 后果"，合格判定仍只在真实取证后由 owner 验收。
3. **编号策略交给用户**。`source.job_id` / `operation_id` 不再由代理定策略：接口与界面提供**可填写位置**，
   并允许显式选择"不使用"。代理不得自行铸造标识并把它当作来源证据展示。
4. **三方素材与字库移出项目范围**。字体库与第三方素材的权利判定不再是本项目的缺口、待办或阻塞依赖；
   仍保留的只是既有边界（不默认上传客户素材、不持有用户素材库、不访问 E 盘）。
   任何活面若把它列为缺口，按本条改写。
5. **设计合同的批准权后置**。`DESIGN.md` 在真实测试前不进入"已批准"状态；本轮按 owner 指令
   先把业界最专业的设计规范收入库内作为参考素材，落地后的验收由 owner 自行测试。
   第 5、6 项（逐条配色归属、品牌蓝裁定）因 owner "我现在看不见"而**挂起，不是阻塞项**，
   不得再作为开工前提反复请示。

   保留标准、通用、版本化的公共接入接口。
