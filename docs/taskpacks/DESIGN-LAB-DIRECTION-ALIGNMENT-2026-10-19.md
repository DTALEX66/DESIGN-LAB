## 2. 正式定位

DESIGN-LAB（设计实验室 / Visual Design Lab）是面向职业视觉设计的 AI 原生、平台中立的**专业视觉智能与可复用设计能力系统**。它把视觉知识、审美判断、设计方法、参考图分析、提示词工程和成功/失败案例，转化为可检索、可组合、可测试、可版本化、可部署的能力；支持用户和 Agent 进行专业视觉分析、提示词生成与反推、设计能力检索，并通过 API、MCP、原生插件、脚本或受控 UI 自动化调用设计软件。经用户或获授权 Agent 验收的知识形成候选，再按 AAOS 正式流程提交审核。

产品本体：**视觉智能 + 审美能力工程化 + 设计能力库 + 设计软件自动化 + 受控知识回流**。

不是：画布、通用编辑器、完整设计工作台或全流程设计文件交付平台。原生宿主负责画布内的实际编辑。

## 3. 六大能力域

每个域都必须有输入、输出、边界与验证方式；实现映射与缺口见验收报告。

### 3.1 Visual Intelligence

- 输入：文字需求、参考图、设计截图、成品图、反馈。
- 输出：构图、层级、风格、字体、色彩、材质、光影及约束的抽取结果；观察 / 推断 / 不确定性分离。
- 边界：不把模型输出当事实；不替代人工判断；不默认外传素材。
- 验证：固定样本集的抽取一致性、字段完整性、观察与推断的可区分性、失败/低置信标注。

### 3.2 Aesthetic Analysis

- 输入：视觉产物及其上下文。
- 输出：构图、版式、字体、颜色、比例、留白、可读性、品牌一致性、原创性、AI 廉价感、模板感的分析；客观可测项 / 专业判断 / 个人偏好分别标注。
- 边界：不以单一分数冒充专业结论；不虚构评分；不以 VLM 自评代替人工接受。
- 验证：专家评分与规则/模型结果的可比性、维度区分度、盲评一致性、反例覆盖。

### 3.3 Prompt Intelligence

- 输入：文字需求，或图像/截图。
- 输出：结构化视觉提示词；图像反推描述与提示词；按目标模型/工具转换；推断与不确定性标注。
- 边界：不宣称能精确还原原始 Prompt；不绑定单一模型。
- 验证：目标模型/工具上的可执行性、结构字段完整性、跨模型转换一致性、人工可用性评审。

### 3.4 Design Capability Library

- 输入：Skills、插件、组件、提示词、规则、参考方法、失败案例。
- 输出：发现、分类、去重、许可核验、提炼、标准化后的能力条目；按领域、审美、风格、任务、产物、宿主和资格状态检索。
- 边界：不以星数代替质量；未核验权利/版本的资源不得标为合格能力；状态不得合并成一个“完成”。
- 验证：来源/许可/版本字段完整性、去重与分类一致性、隔离测试与真实任务测试记录、资格状态可追溯。

### 3.5 Creative Tool Automation

- 输入：任务与目标宿主。
- 输出：经官方 API/SDK → 原生插件 → MCP → 脚本/CLI → 受控 UI 自动化分层选择的可执行调用；权限、输入输出、调用状态、读回、错误处理与恢复记录。
- 边界：不成为通用 Agent Runtime / 跨项目调度器；MCP 握手、HTTP 200、退出码或截图都不能替代真实任务验证。
- 验证：宿主/版本、Schema、权限、数据流、超时/取消、读回、失败模式、恢复/回滚、许可证与安全限制逐项声明并有真实任务证据。

### 3.6 Knowledge Candidate & Evaluation

- 输入：经真实样本测试与用户/授权 Agent 验收的能力或经验。
- 输出：带来源、许可、版本、适用范围、测试结果和验收身份的知识候选，提交 AAOS。
- 边界：只提交候选并读取 AAOS 状态；不得绕过审核直接写入可信知识；能力验收不自动等于 AAOS 知识已验证。
- 验证：候选字段完整性、验收主体/时间/理由、哈希与撤回信息、AAOS 接收状态回读。

## 5. 能力生命周期与状态分离

发现 → 来源/许可/版本核验 → 分类去重 → 方法提炼 → 中立能力定义 → 原生适配 → 隔离测试 → 真实任务测试 → 读回/失败验证 → 用户或授权 Agent 验收 → 能力资格确认 → 生成知识候选 → AAOS 正式审核/接收。

以下状态同样不可混为一谈：**文档修订 ≠ 规划完成 ≠ 代码实现 ≠ 真实运行 ≠ 人工验收 ≠ AAOS 接收**。

## 6. 模型策略

支持本地、云端和混合模型，不绑定单一 Provider。按视觉能力、中文理解、审美基准表现、工具调用可靠性、隐私、成本、延迟和可用性路由。

- 本地模型用于其能力覆盖的隐私敏感、高频、低成本和结构化任务；多模态能力须实测。
- 云端模型用于复杂多图分析、困难审美推理和本地能力不足的任务；数据发送须经授权。
- 可本地预处理后仅将获准的最小必要数据交给云端；服务不可用时降级到本地或人工。
- 模型输出是候选判断，不自动成为事实或知识。
- “本地可运行”不等于“职业级审美合格”，必须使用基准样本和人工评审。

## 8. 与 WORK-LAB / AAOS 的边界

### WORK-LAB

- WORK-LAB 拥有：通用工作流、Work Unit、全局配置/策略、权限与预算、跨项目路由、执行协调、运行监测、维护/恢复和通用回执。
- DESIGN-LAB 拥有：视觉领域定义、审美方法、提示词能力、设计能力 Registry、专业评价标准及设计工具能力规范。
- 通过版本化 Schema/API/Manifest/Adapter/Receipt/Candidate 协作，不直接写对方私有数据库。
- 简单视觉任务可以直接使用 DESIGN-LAB；跨软件、多步骤、需统一授权或恢复的任务可请求 WORK-LAB，不强制所有设计任务经过 WORK-LAB。

### AAOS

- AAOS 是正式知识、来源/证据治理、审核和长期学习的权威。
- DESIGN-LAB 可维护设计运行所需的 Registry、方法卡、能力定义、评测集和操作规则，但不能取代 AAOS 的正式知识真源。
- 知识候选至少包含：ID、标题/类型/摘要、来源与原始资产引用、版权/许可证、允许用途、隐私/脱敏状态、领域/审美/风格/任务、版本、方法内容、适用条件、反例/失败模式、测试样本、模型/工具版本、结果/局限、验收主体/时间/理由、哈希与撤回信息。
- DESIGN-LAB 只提交候选并读取 AAOS 返回的接收/审核状态；不得绕过审核直接写入可信知识。
