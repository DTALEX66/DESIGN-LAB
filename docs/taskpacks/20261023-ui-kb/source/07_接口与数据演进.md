## 拟增能力，不是已上线 API

知识条目与修订 CRUD、分页检索、软件/模型/入口档案、中立方案/目标渲染、导出与反馈应在现有 Python 服务增量实现。路由命名在现有路由合同中确定，不在本包伪造一套已上线 URL。新增路由同时更新 Schema、边界/绑定表、前端调用与错误状态，并走服务端和浏览器测试。

## 建议对象映射

- KnowledgeEntry：优先复用已有 Source/Method/Capability 定义，增加可编辑正文和修订引用；一个权威写入点，索引可重建。
- TargetProfile：软件、Agent、模型、提供方、版本、入口、任务模式与能力字段；未知可空并解释原因，不能自动补支持。
- AssistancePlan：复用 Brief/Direction/PromptResult 的引用，保存中立创意、品牌/角色约束、镜头声音、外部步骤、已知缺口与资料修订。
- HandoffExport：人可读说明 + CSV/JSON；携带版本与执行状态，导出不改变 sent/executed。
- Feedback：用户可选提供结果、维度结论、时间码及当时版本；未反馈不是失败，也不是接受。
- KnowledgeCandidate：沿用现有合同。未来外发前再检查来源、权利、隐私、测试、接受和撤回信息；当前 outbound=NOT_CONNECTED。

内部对象 ID 可以由系统生成，外部 source.job_id / operation_id 必须由用户提供或明确不用，不能伪造为来源证据。

## 演进规则

旧记录不可变。未知字段按合同拒绝或保留，不偷偷丢失。兼容新增字段先列消费者；不兼容变化升版本并做迁移/回退测试。编辑需 expectedRevision 或等价前态条件；导出固定依赖快照。新增推理结果必须真实标注执行情况，不能复用旧 const false 的表去存 true 或移除守卫以“通过”。

私有数据不因软件可选而默认外传；端点配置不记录明文认证到交接包。普通用户界面只显示必要选择与后果；JSON、schema、源路径、trace 进高级详情。
