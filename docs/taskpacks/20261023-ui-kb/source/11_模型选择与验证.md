# 轻量底座模型方案

当前建议先测一个 Qwen3.5-4B GGUF 量化候选，匹配视觉组件，8K上下文、并发1作为起步。Qwen3.5-9B是质量升级候选；Gemma4 E4B可作多模态对照。27B不作为默认常驻日常模型。没有本机速度/显存实测，不给 token/s 保证。

用户机器：Windows11企业版LTSC、i5-14600KF、64GB RAM、RTX5060 8GB。系统桌面、浏览器和设计软件也使用资源，不能把8GB全部视为模型空闲显存。量化文件大小≠运行峰值；上下文、图片和并发都影响占用。Gemma的E是有效参数，不是总参数简单等价；MoE激活参数也不是总加载体积。

验证至少五组：中文需求整理；一张参考图观察/推断分离；依据规范给有引用的设计建议；同一意图适配两个目标档案；软件问题摘要。分别记录提示/输出、正确与遗漏、首字/总耗时、RAM/VRAM、超时/失败。真实设计质量由用户判断。官方 benchmark只能帮助筛选，不能代替专业审美样例。

方案助手、执行Agent的模型、媒体生成模型是三个角色；不要把H3等媒体模型当作知识库底座。本地4B负责日常，复杂任务用户可切云端；三个项目可选同一外部服务，但当前不为此做项目联调或共享数据库。知识检索、编辑、复制不依赖推理在线。

不需要先训练模型。先用精选知识检索与模板；确有检索失败样例再引入embedding。图片理解不等于音频理解；视频抽帧只支持已观察画面，不宣称听过原音轨。大媒体先限定范围，未知照实写明。
