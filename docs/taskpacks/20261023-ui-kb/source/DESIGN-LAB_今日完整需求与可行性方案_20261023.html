方案 / 01

定位与责任

DESIGN-LAB 是覆盖品牌、平面、UI/UX、3D、2D/3D 动效、粒子特效、视频与音频的专业设计知识管理、创意方案与模型应用辅助系统。它整理和更新设计规范、审美方法、叙事与视听语言、提示词、模型和软件使用指南及实践案例；根据用户的内容、目标、参考资料和所选工具组合，提供有依据的分析、重构方向、专业方案、脚本分镜、声音设计、提示词、参数建议与外部执行说明。

用户决定采用、修改、试用或放弃；外部软件、Agent 和模型实施制作。DESIGN-LAB 不承担项目制作落地、成品交付、发布，不建设第二套 Agent、模型网关、画布、3D 编辑器或剪辑时间线。自动操作外部软件归入未来能力；当前能提供可人工交接的操作说明或脚本草案，生成脚本不等于运行脚本。

本项目的可验证价值是：知识找得到、依据看得懂、方案有专业内容、输入能适配目标工具、材料可以带走、旧版本可追溯、用户反馈能用于修正方法。没有外部结果时只声称“方案已提供/未验证”，不能声称成片已完成或模型效果已合格。

方案 / 02

决策优先级与范围

本方案以本会话用户最新明确决定为需求依据。早先“完整制作交付”“自动调用软件”的扩大解释被后续澄清替代；自动化保留为未来研究。跨媒介覆盖、专业接口、标准接口、开源复用、用户自主选择、桌面轻量化均保留。知识将来可对接 AAOS，但现在三个项目各自独立：不联调、不发送、不依赖对方启动，不把联动列为当前缺口。

当前规划范围：知识与提示词管理；来源与版本；参考分析和反推；多内容类型的方法模板；软件/Agent/模型组合选择；方案与交接材料；本地结果版本；可选外部反馈；轻量桌面 UI；必要的底座模型接口。

未来能力：软件自动操作、自动派发、多 Agent 协同、成片自动生产、跨项目联动、AAOS 传输及接收回读。手机端排除。字体库、第三方素材库及其完整权利管理不扩入项目；既有来源许可和不默认外传客户资料的边界继续保留。

模型接入是本方案的后续实施项，不是本轮已经执行的功能。本轮不修改仓库权威或产品代码，不下载安装模型，不消耗媒体生成额度。原有 E3/E4、宿主与发布记录不因新规划自动升格。

六个任务维度

方案 / 04

四条用户旅程

旅程 A：灵感参考 → 观察/推断分离的拆解 → 提炼可借鉴方法 → 加入用户自己的内容与想法 → 重构方向 → 面向所选工具的提示/步骤。图片反推提供可用描述，不宣称还原原始提示词；不把参考中的每个细节都照搬为用户设计。

旅程 B：正在开发的产品 → 定位/受众/卖点 → 共享品牌表达 → UI/UX 信息与交互建议、VI、宣传物料及视频声音方案 → 分别交给外部工具。不同媒介共享品牌约束。UX 需结合使用任务和验证，不能用漂亮截图代替可用性。项目负责方案，不承诺实现界面或交付品牌成品。

旅程 C：小说/广告/漫画/说唱等内容 → 内容与叙事分析 → 创意脚本 → 分镜和声音设计 → 所选软件/Agent/模型的执行材料。短剧/漫剧有角色手册、场景关系、集间连续性与钩子；说唱/MV有歌词结构、BPM/节拍、语速、重音和镜头节奏；粒子方案说明用途与轨迹要求，不许用“一键高级特效”代替设计。

旅程 D：导入规范/提示词/指南/实践案例 → 分类去重与来源登记 → 编辑、比较和版本保存 → 搜索与引用 → 用户试用 → 自愿反馈 → 修正方法。常用知识管理可以在模型离线时完成；不要求用户每次复制都先审批、署名或提交反馈。

方案 / 05

知识库与更新机制

统一条目类型：设计原则与规范、模型使用指南、软件/Agent 适配说明、提示词模板、制作配方、成功/失败案例。知识条目可关联参考，但不建立完整客户素材 DAM 系统。初期优先支持文本、Markdown、JSON/CSV 元数据、链接登记与用户选择的图片；PDF/Office 解析按需接入，视频先接受用户关键帧、已有文字观测或限定片段，音频先接受文字稿与声音要求。原始输入、抽取成功、理解成功三个状态分别记录。

最低字段：内部 ID、类型、标题、摘要、领域/任务标签、正文、适用条件、反例与限制、来源 URL/章节/页码或时间码、来源版本与观察时间、许可或引用范围、内容摘要、修订号、替代关系。字段缺失写未知，不以链接存在认定已核验。

规则分为平台硬规格、品牌要求、专业建议、用户偏好。冲突时优先解释冲突和适用范围，审美偏好不能当普遍真理。用户可覆盖建议，规格约束仍明确提示。

更新顺序：发现变化 → 生成候选差异 → 绑定受影响的模板/配方 → 样例核对 → 发布新修订 → 保留旧版本与回退。latest 不自动等于推荐版本；旧方案固定当时所用资料和配置，不跟随更新悄悄变化。手动导入与检查先做，后台定时收集留作后续，不默认创建自动化任务。

来源等级分开：官方文档的能力声明、开源实现的结构证据、本项目实测、用户反馈。热门/高星不是专业质量证据。收录、适配、测试、推荐也分别记录。更新修复主要指规范、提示词、配方和兼容规则修正；修电脑、升级客户端和全局配置不进入 DESIGN-LAB。

方案 / 06

模型与软件适配

核心组合键建议为：软件身份/版本/入口 × 模型身份/版本/提供方 × 任务模式。区域和订阅入口可能影响功能，无法核实时保留 UNKNOWN。模型 API 有某功能，不推出桌面客户端开放了该功能。

适配档案记录：输入模态、支持的参考角色、素材数量与格式限制、时长/画幅/分辨率范围、提示风格、是否有负向输入、可用参数、参数设置位置、输出形态、已知冲突、官方依据、测试日期和退路。参数不得凭空发明；未知参数作为建议问题或未验证项，不输出成能直接执行的 JSON。

匹配分两步：先排除已知不兼容，再对兼容候选给可解释理由。用户仍能保留“仅规划”的未验证路线，但系统不能标它已可执行。不做没有样本依据的“最强榜”和虚构百分制评分。平台主要比较入口与工作组织能力；模型主要比较角色/产品一致性、镜头/动作、风格、文字、声音、连续性、修改能力和成本时延，二者不混评。

保持一份中立创意意图，再分别渲染为工具专用材料。更换模型时保留故事、品牌、镜头目的与素材角色；报告哪些能力无法迁移、需要重新生成什么。不把旧参数原样搬到新模型。

适配材料至少三种：创意脚本、镜头与声音脚本、工具执行说明/脚本草案。软件脚本仅供用户检查后交给外部工具；本项目当前不运行它，不启动外部 Agent，不自动发送。支持 Markdown/纯文本、分镜 CSV、结构化 JSON 导出。未来 OTIO 等交换格式仅在需求和兼容测试成立后接入。

方案 / 07

提示词专业化的研究结论

专业性来自清晰设计决定、有效参考和模型适配，不等于越长越好。[S10–S17]

图像：说明主体、用途、构图、层级、材质和光线；编辑时明确改哪里、保留什么。图生视频：参考图承担外观信息，提示往往集中于运动与镜头；多镜头/对白按模型支持拆分。3D：形体、材质、风格和技术约束共同起作用，输入图与后处理选择也重要。音乐：风格、情绪、乐器、节奏、结构与制作质感；配音：脚本、声音、语气、发音和停顿；音效：声源、动作、空间、起落与时长。三类音频不能用同一个万能模板。

Runway Gen-4 官方强调简洁与正向表达；Meshy 允许排除描述；因此负面词、镜头命令、权重符号及 JSON 格式必须按具体模型版本处理。参考素材、UI 参数和提示正文是不同控制通道，不能把所有要求塞进提示词。[S11/S15]

MiniMax 已有只增强提示、不生成视频的 H3-Context-IR 入口。DESIGN-LAB 应优先复用官方已有辅助能力；核心差异是跨工具知识、设计意图保持、规范关联、版本和案例，而非重复一个通用扩写器。[S09]

方案 / 08

精准传达的边界

可确定验证的部分：材料字段与单位、参考角色、时长算术、参数范围、版本兼容、缺失项、输出格式及来源引用。

只能通过结果判断的部分：审美、角色一致性、镜头路径遵循、口型、文字形状和音乐表达。模型理解一条指令，不等于像原生软件一样精确执行。seed、低温度和更长提示不能被承诺为跨版本完全复现。

对必须精确的品牌文字、产品几何、固定镜头轨迹、节拍落点、粒子数量/碰撞和逐帧合成，应建议外部原生 3D/剪辑/合成工具完成确定性部分，再用生成模型做其适合的视觉变化。白模视频可以作运动参考，但不是所有模型都把它当严格几何约束。

结果反馈记录“符合/部分符合/不符合”的具体维度、问题时间码和修改依据，不因用户采用就升级为通用能力合格。模型自评只能辅助发现问题，不代替用户接受或外部验证。

方案 / 09

白模与镜头路线

用户示例路线可保留为配方：需求与分镜 → 给外部 Agent 的白模/相机说明 → 用户在 3D 软件中得到预演与关键帧 → 按生成模型入口准备参考和提示 → 外部生成 → 用户选择结果并可选回传。Codex、Blender、MiniMax Design、H3 都可替换，不能成为唯一合法组合。

3D 交接记录坐标方向、单位、物体与相机关系、焦段、帧率、时长、画幅、镜头起止状态和导出要求。视频交接说明每份参考用于形体、风格、运动还是声音，并把保留要求与允许变化分开。

官方资料支持 Blender 脚本/命令行渲染、H3 多模态参考与 Adobe Firefly 镜头运动参考，因此这类路线有技术基础；本轮没有操作这些工具、生成样本或验证实际绑定，整链仍为待实测。[S09/S18/S24]

方案 / 10

底座模型与三项目独立

区分三种角色：DESIGN-LAB 的方案助手模型；外部 Agent 自己使用的推理/编码模型；最终生成图像/视频/音频/3D 的媒体模型。它们可以不同。选择了某个视频模型，不表示它负责读规范与组织方案。

用户硬件为 Windows 11、i5-14600KF、64GB RAM、RTX 5060 8GB。优先测试一个 Qwen3.5-4B GGUF 量化候选，8K 上下文、单请求、少量图片作为起步配置；9B 为质量升级候选，Gemma 4 E4B 为多模态对比候选。27B 不作为默认日常主力。这里只是候选和测试建议，不声称本机已装、速度达标或审美合格。[S27–S30]

底座服务可以由三个项目各自通过标准接口连接同一外部推理服务；共享计算不等于共享聊天、任务和业务数据库。当前不为共用而联调三个项目，不让 DESIGN-LAB 依赖 AAOS/WORK-LAB 启动。各项目单独配置、单独上下文，服务不可用时知识搜索、编辑、模板复制仍能用。

专业知识首先通过检索提供给模型，不认为模型会自动学会新增知识。先做关键词、标签、全文；向量检索或小型 embedding 只在检索失败样例证明需要时补充。复杂多图、长内容和困难审美判断可由用户切换云端模型；实际请求前说明发送的数据，保持本地路径可选。

方案 / 11

最小技术架构

保留现有 apps/workbench 的 Vanilla TypeScript + Vite、src/design_lab 的 Python 服务、既有 SQLite 状态与 JSON Schema；不换前端框架，不新增第二运行时或并列事实库。[S01–S05]

实现顺序建议：知识条目/来源/修订 → 搜索 → 软件与模型档案 → 中立方案 → 目标格式转换 → 本地方案版本 → 导出 → 自愿反馈。新能力在现有服务中模块化扩展，模板与档案优先数据化，不为每个模型新增一套页面和服务。现有 Brief/Reference/Direction/PromptResult 等对象先评估扩展复用，不能照抄本包另起新体系。

SQLite FTS5 可作为轻量全文索引。中文必须有专门验收：默认分词不应被假定能理解中文词义；trigram 的 MATCH 对不足三个 Unicode 字符不命中。小规模阶段对“分镜”“粒子”等短词采用有界 LIKE/标签回退，或实测后选中文分词；不得因英文检索通过就宣布中文可用。[S20]

索引可重建，规范正文及修订只有一个可变真源；导出文件是快照。删除、恢复、引用失效和并发编辑均需约定，编辑使用版本前置条件避免覆盖。独立备份/恢复在本项目内验证，不靠 Git 存客户任务数据。

重型解析按需后台运行，不阻塞首屏。Docling 可作可选文档解析候选，但代码许可与随附模型许可分别核对；不让“支持 PDF”变成默认下载一堆模型的前置条件。[S22]

方案 / 12

仓库差距与复用落点

本轮 exact SHA 为 2d6ede51cd0f49e9b99c27f09924a0db29843b89。代码阅读确认：prompt_intelligence.py 不调用模型；prompt_results.py 存储层要求 executed=false；model_selection.py 记录选择；capability_library.py 是已维护来源和模型记录的只读投影，不能当成用户可编辑知识库。[S01–S05]

可复用：单一前端壳、同源服务、SQLite、追加式提示结果修订与摘要、来源记录、模型选择、版本化合同和现有知识候选导出。待开发：知识/提示词管理写入界面与对应 API、中文检索、软件×模型×入口档案、跨媒介任务模板、中立方案和导出、可选反馈、真实助手推理路径及其运行记录。

模型目录与端点的可靠绑定仍需补齐。真实助手推理不能把旧 executed=false 的合同直接写成 true；应做明确的版本演进或独立运行记录，保留旧结果的真实含义。选择成功、连接成功、返回文本、内容可用四件事分别验证。

旧项目定义含未来生产交付和自动化内容，后续落仓时按本会话最新范围修订活动阅读面与唯一任务账本；保留历史取代关系，不凭旧 DONE 关闭新需求。新方案是研究与规划交付，不是宿主 E3、真人 E4 或发布证明。

方案 / 13

轻量界面与交互

三个日常入口：设计辅助、知识与提示词库、我的方案。设置只放模型服务、目标工具档案、导入更新、备份与诊断。AAOS 不出现在当前主导航；未来接口信息可放高级设置的合同说明，无连接按钮与未接入红灯。

设计辅助初始只露出需求输入、参考附件和输出类型。工具/模型组合允许稍后选；展开时区分“方案助手”和“外部制作目标”。结果页用一份可读方案为主体，创意/分镜/工具材料作为上下文页签或折叠段，不做聊天气泡流、节点画布、多 Agent 控制台。一个状态下最多一个主要动作；复制/下载与实际发送严格区分。

知识库采用搜索 + 标签 + 列表，详情按需打开；版本/来源/测试证据不常驻堆在首页。我的方案列最近内容，支持继续编辑、复制一份与版本比较。新版本不覆盖历史；复制不强迫具名审核，既有正式审核保留为明确区分的“标为验证可用”操作，不伪造审核身份。

珍珠白和炭黑保持专业克制。玻璃仅用于顶栏、侧栏或临时面板；正文和长列表保持稳定实底，兼容关闭透明效果。Windows 风格窗口控制和 Ctrl 快捷键；不为这个桌面项目新增手机端。

正文建议 14–16px，次要元数据不低于 12px；文字与状态有清晰对比，颜色不作为唯一提示。表单有明确标签与错误原因。离线、空数据、保存失败、目标不兼容、模型不可用都给可继续操作的下一步。[S31–S33]

方案 / 14

性能预算与可用性验收

以下都是建议目标，尚未执行测量：首屏 JavaScript gzip 不超过 150KB，重型编辑器/解析/模型目录延迟加载；长列表分页或窗口化，初始最多 50 行；附件先生成缩略图，媒体不自动播放；不加载第三方远程字体，不持续动画，不为了展示状态高频轮询。

在约定样例机与浏览器上，以 1,000 条真实结构的测试记录测本地搜索 p95≤300ms，普通操作反馈目标≤100ms；AI 推理单独测首字延迟、总时长、内存/显存与超时，不混入界面指标。上述预算须先量基线，再决定调整，不能靠隐藏字段伪装变快。

桌面测试尺寸：1280×800、1440×900、1920×1080，以及 Windows 125%/150% 缩放。验证键盘焦点、长中文标题、空态、错误、旧版本、附件缺失、不兼容目标。安排至少 3 位目标用户做无指导任务：导入一条知识、找两字中文词、从参考获得方案、切换目标模型、复制交接、恢复旧版。记录完成过程与卡点，不以主观 8/10 代替测试。

方案 / 16

可行性与剩余风险

工程可行性较明确：知识管理、版本、检索、档案、参数校验和导出均有成熟技术与现有代码落点。内容质量可行但需验证：专业方案依赖高质量知识、正确参考和目标模型能力，不能由模板存在保证。外部精准生产及自动化不属于当前闭环，本轮无实测结论。

主要风险与对策：知识过多但检索无效→小规模精选与中文查询集；模型更名/入口变化→版本快照与差异；提示词万能化→目标档案；输入媒体有而理解链未接→分别显示导入/解析/分析；多模型拖慢本机→一款助手模型起步；知识更新污染旧方案→固定修订；界面因全品类再次膨胀→一个任务表单、按需模块；用户复制之前被审核阻塞→试用与正式推荐分开。

外部服务、地域、订阅、价格与许可会变；记录观察日期，不作永久承诺。Seedance 2.5 本轮确认到官方指南入口，但页面正文未完整取回，其限制不进入已核验可执行档案。其他厂商“工业级一致性”等宣传也不作为本项目实测结论。[S34]

未来另行考虑自动操作和 AAOS 联动。各阶段都交用户可运行的纵切，不做连续多轮只有治理文档或全后端没界面。没有测试证据不翻绿，没有用户使用验证不宣称专业接受。

分阶段实施与验收

以下阶段标签用于本方案排序，不是新建第二套项目任务账本。落仓时映射现有 CURRENT 与唯一 ledger，原冻结状态不伪改。

阶段 A：需求收口与最小知识库

复用既有 Source/Method/Capability 合同。明确现有可写数据与只读投影，建立条目导入、编辑、追加修订、来源详情和搜索。先约 30 条精选种子内容，覆盖三组：品牌/UI；图像/3D；视频/音频。由项目实际需要选取，不靠条目数量证明质量。

验收 A1：用户从界面新增条目，重启后标题、正文、来源和版本仍一致。 验收 A2：修改生成新修订；旧版内容摘要不变；并发覆盖有冲突提示。 验收 A3：“分镜”“粒子”“品牌”和英文型号检索均有预期结果；无结果有说明，不伪造相关条目。 验收 A4：相同来源不同版本保留；重复导入有可解释处置；缺许可写未知。 验收 A5：模型服务关闭时仍可检索、编辑和复制。

阶段 B：独立方案与目标适配

复用 Brief/Reference/Direction/PromptResult 的可用部分，增加中立设计意图及软件/模型/入口档案；首批约 4 个有官方依据的档案，先验证提示/参考/参数导出。前端只增加上下文控件，不增四套工作台。短任务不强迫用户先建完整项目，必要内部工作区通过现有对象承接；内部 ID 与用户提供的外部 job_id 分开。

验收 B1：从需求与参考得到带依据和局限的方案，保存、重启读回。 验收 B2：切换目标模型，原创意和品牌约束保留，参数及参考角色重新校验。 验收 B3：未知入口只能导出标明未验证的规划材料；已知不兼容项清楚说明，不伪造支持。 验收 B4：Markdown/TXT、分镜 CSV、JSON 导出信息一致，含版本和未执行声明。 验收 B5：没有执行 Agent、外部媒体生成或自动发送的副作用；复制和正式认可分开。 验收 B6：参考仅作为链接登记时，不显示“已分析图片/视频”；缺少输入能继续手动补充。

阶段 C：方案助手模型

先核实现有端点与硬件，选择一个模型服务接入；通常先试 4B 量化。先修模型目录/端点关联和失败状态，再开真实请求；模板渲染与推理生成用不同真实运行记录。既有 executed=false 合同不能悄悄翻义。

验收 C1：记录实际模型、版本/量化、推理服务版本、输入/输出摘要、请求状态与局限。 验收 C2：文本成功不推出图片可用；明确测试图片输入；无音频输入能力不显示听过音频。 验收 C3：断连、超时、取消、无效响应、上下文过长都有可恢复路径，原稿不丢。 验收 C4：本地/云端可替换；请求前可见发送内容范围；没有模型时仍可使用知识与模板。 验收 C5：目标机器记录首字/总延迟、RAM/VRAM 峰值，按真实设计任务评价，不引用厂商 benchmark 当验收。

阶段 D：专业内容与外部反馈

深化小说/短剧/漫剧、品牌物料/宣传片、MV/说唱、3D/粒子等内容模板。用户可手动附外部结果、时间码和修改意见；反馈可选，不自动训练、不自动资格认证。

验收 D1：三个包内示例能用同一产品结构完成，不需新增三套 runtime。 验收 D2：长篇内容明确已读章节与未知范围；角色与场景连续性可版本化。 验收 D3：BPM/节拍/帧率换算有单位；要求精确同步时提出外部剪辑建议。 验收 D4：外部结果的成功/失败绑定当时资料和模型版本，不污染全部模板。 验收 D5：回退知识推荐版本后，旧方案仍可读；失效来源可标记并替换。

UI 与性能验收（目标，未执行）

在 1280×800、1440×900、1920×1080 与 Windows 125%/150% 下验证三主入口、长中文、键盘、错误和离线状态。至少 3 位代表用户做 6 项无指导任务，记录卡点，不把机器几何检查当用户理解。

首屏 JS gzip≤150KB；列表初始≤50行；1,000 条结构样例本地搜索 p95≤300ms。实际模型延迟另报。若现有构建超过预算，先测模块与资源再改；不能为了轻量化删除必要内容或换栈。

交接场景示例（人为编写的规划材料，未执行生成）

一：产品品牌与宣传片，含3D白模和粒子

输入：一个桌面工具即将进入宣传期，希望清晰、克制地表达“更快找到需要的方法”。示例不是对任何已审计产品能力的真实宣传声明。

共享约束：珍珠白/炭黑背景、单一品牌强调色、真实界面文字由后期叠加、产品轮廓保持。输出包：UI/VI/UX方向说明、海报/封面物料清单、15秒宣传片分镜与声音要求、目标工具交接。

镜号时长画面与目的相机/运动声音外部制作约束
015秒简化白模桌面物体建立空间缓慢推进，主体稳定轻环境声渐入3D软件出预演，焦段/单位随工程说明，不在DL运行
025秒粒子从分散到有序，表达归纳相机基本稳定，粒子运动承担变化单次清楚的聚合音效精确粒子路径外部仿真；生成模型仅补视觉，不承诺粒子计数
035秒产品展示与品牌结尾镜头减速定格音乐收束，旁白可选Logo与UI真实文字在外部后期保证

给外部Agent：建立简化几何和相机预演，明确单位/帧率/画幅，导出分镜关键帧和预演视频；不修改原始产品工程。给媒体模型：参考A控制产品外形，参考B控制镜头运动，参考C控制材质风格；分别写保留与可变化内容。若目标入口不收视频参考，退回关键帧或换已验证入口。DL当前仅导出这些材料。

二：原创小说片段转漫剧/短剧方案

输入范围：用户提供的一段原创故事“雨夜车站，两人因错拿笔记本相遇”。仅分析已给段落，不宣称读过全书。

方案：人物A急促但克制；人物B冷静；场景是同一站台，同一雨势与服装。先给用户两个方向：二维漫画叙事或实拍感短剧，各自说明制作复杂度和需要的参考。角色手册/场景手册与镜头版本分开。

三镜草案：站台远景交代关系 → 笔记本特写形成误会 → 双人中景对白揭示线索。对白文本、人物视线、屏幕方向、镜头顺序和环境声明确。选择模型后再根据其时长、角色参考和原生音频支持拆分；不预先承诺长篇多集身份完全一致。连续性问题可手动反馈并修订手册。

三：说唱/MV与独立音频方案

输入：用户自己的16小节歌词，示例节拍90BPM、4/4。节拍数值是任务假设，不是实际音轨测量。

设计：按前奏/主歌/副歌/收尾组织，不强迫每一句都切镜。声音方案列演唱方式、语速与重音、伴奏密度和混音空间；画面方案列角色/地点/动作/节拍点与粒子或2D图形用途。音乐、配音、音效分别给目标模板，不一段词通吃。

算术：90BPM时每拍2/3秒，一小节8/3秒，16小节128/3秒；最后以实际音轨与外部剪辑工程为准。逐拍精准同步通过外部剪辑，不承诺生成视频自动对齐。用户可只使用音乐建议或只复制镜头脚本，无需启动其他项目。
