# 分阶段实施与验收

以下阶段标签用于本方案排序，不是新建第二套项目任务账本。落仓时映射现有 CURRENT 与唯一 ledger，原冻结状态不伪改。

## 阶段 A：需求收口与最小知识库

复用既有 Source/Method/Capability 合同。明确现有可写数据与只读投影，建立条目导入、编辑、追加修订、来源详情和搜索。先约 30 条精选种子内容，覆盖三组：品牌/UI；图像/3D；视频/音频。由项目实际需要选取，不靠条目数量证明质量。

验收 A1：用户从界面新增条目，重启后标题、正文、来源和版本仍一致。
验收 A2：修改生成新修订；旧版内容摘要不变；并发覆盖有冲突提示。
验收 A3：“分镜”“粒子”“品牌”和英文型号检索均有预期结果；无结果有说明，不伪造相关条目。
验收 A4：相同来源不同版本保留；重复导入有可解释处置；缺许可写未知。
验收 A5：模型服务关闭时仍可检索、编辑和复制。

## 阶段 B：独立方案与目标适配

复用 Brief/Reference/Direction/PromptResult 的可用部分，增加中立设计意图及软件/模型/入口档案；首批约 4 个有官方依据的档案，先验证提示/参考/参数导出。前端只增加上下文控件，不增四套工作台。短任务不强迫用户先建完整项目，必要内部工作区通过现有对象承接；内部 ID 与用户提供的外部 job_id 分开。

验收 B1：从需求与参考得到带依据和局限的方案，保存、重启读回。
验收 B2：切换目标模型，原创意和品牌约束保留，参数及参考角色重新校验。
验收 B3：未知入口只能导出标明未验证的规划材料；已知不兼容项清楚说明，不伪造支持。
验收 B4：Markdown/TXT、分镜 CSV、JSON 导出信息一致，含版本和未执行声明。
验收 B5：没有执行 Agent、外部媒体生成或自动发送的副作用；复制和正式认可分开。
验收 B6：参考仅作为链接登记时，不显示“已分析图片/视频”；缺少输入能继续手动补充。

## 阶段 C：方案助手模型

先核实现有端点与硬件，选择一个模型服务接入；通常先试 4B 量化。先修模型目录/端点关联和失败状态，再开真实请求；模板渲染与推理生成用不同真实运行记录。既有 executed=false 合同不能悄悄翻义。

验收 C1：记录实际模型、版本/量化、推理服务版本、输入/输出摘要、请求状态与局限。
验收 C2：文本成功不推出图片可用；明确测试图片输入；无音频输入能力不显示听过音频。
验收 C3：断连、超时、取消、无效响应、上下文过长都有可恢复路径，原稿不丢。
验收 C4：本地/云端可替换；请求前可见发送内容范围；没有模型时仍可使用知识与模板。
验收 C5：目标机器记录首字/总延迟、RAM/VRAM 峰值，按真实设计任务评价，不引用厂商 benchmark 当验收。

## 阶段 D：专业内容与外部反馈

深化小说/短剧/漫剧、品牌物料/宣传片、MV/说唱、3D/粒子等内容模板。用户可手动附外部结果、时间码和修改意见；反馈可选，不自动训练、不自动资格认证。

验收 D1：三个包内示例能用同一产品结构完成，不需新增三套 runtime。
验收 D2：长篇内容明确已读章节与未知范围；角色与场景连续性可版本化。
验收 D3：BPM/节拍/帧率换算有单位；要求精确同步时提出外部剪辑建议。
验收 D4：外部结果的成功/失败绑定当时资料和模型版本，不污染全部模板。
验收 D5：回退知识推荐版本后，旧方案仍可读；失效来源可标记并替换。

## UI 与性能验收（目标，未执行）

在 1280×800、1440×900、1920×1080 与 Windows 125%/150% 下验证三主入口、长中文、键盘、错误和离线状态。至少 3 位代表用户做 6 项无指导任务，记录卡点，不把机器几何检查当用户理解。

首屏 JS gzip≤150KB；列表初始≤50行；1,000 条结构样例本地搜索 p95≤300ms。实际模型延迟另报。若现有构建超过预算，先测模块与资源再改；不能为了轻量化删除必要内容或换栈。
