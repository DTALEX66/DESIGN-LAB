# DESIGN-LAB 权威定位与方向调整任务包

## 任务目标
将 DESIGN-LAB 的正式定位纠正为“专业视觉智能与可复用设计能力系统”，而非画布编辑器、完整设计工作台或设计文件交付平台。以最小差异更新现有权威文档和任务映射，保留有效实现、历史证据和原始资料。

## 正式定位
DESIGN-LAB（设计实验室 / Visual Design Lab）是面向职业视觉设计的 AI 原生、平台中立的专业视觉智能与可复用设计能力系统。它把视觉知识、审美判断、设计方法、参考图分析、提示词工程和成功/失败案例，转化为可检索、可组合、可测试、可版本化、可部署的能力；支持用户和 Agent 进行专业视觉分析、提示词生成与反推、设计能力检索，并通过 API、MCP、原生插件、脚本或受控 UI 自动化调用设计软件。经用户或获授权 Agent 验收的知识形成候选，再按 AAOS 正式流程提交审核。

## 六大能力域
1. Visual Intelligence：理解文字需求、参考图、设计截图、成品图和反馈；抽取构图、层级、风格、字体、色彩、材质、光影及约束；区分观察、推断和不确定性。
2. Aesthetic Analysis：分析构图、版式、字体、颜色、比例、留白、可读性、品牌一致性、原创性、AI 廉价感和模板感；分别标注客观可测项、专业判断与个人偏好。
3. Prompt Intelligence：从文字需求生成结构化视觉提示词；从图像/截图反推视觉描述和提示词；按目标模型/工具转换；标明推断与不确定性，不宣称能精确还原原始 Prompt。
4. Design Capability Library：发现、分类、去重、核验许可、提炼和标准化 Skills、插件、组件、提示词、规则、参考方法和失败案例；按领域、审美、风格、任务、产物、宿主和资格状态检索。
5. Creative Tool Automation：通过官方 API/SDK、原生插件、MCP、脚本/CLI，必要时使用受控 UI 自动化；明确权限、输入输出、调用状态、读回、错误处理和恢复。
6. Knowledge Candidate & Evaluation：使用真实样本测试，由用户或获授权 Agent 验收；生成带来源、许可、版本、适用范围、测试结果和验收身份的知识候选，提交 AAOS 正式接收。

## 明确非目标
- 不建设第二套 Photoshop/Figma/Blender 画布、通用编辑器或完整设计软件替代品。
- 不以全流程编辑、制作和最终文件交付作为产品本体。原生宿主负责画布内的实际编辑。
- 不成为通用 Agent Runtime、聊天客户端、模型网关或跨项目调度器。
- 不接管 WORK-LAB 的通用工作流、全局配置、权限/预算、跨项目协调、运行监测和维护。
- 不取代 AAOS 的正式知识真源、来源/证据治理、审核与长期 Human–AI 学习。
- 不把热门资源或模型输出直接认定为合格能力/可信知识。
- 不默认上传客户素材、私人资料或未经许可的第三方资产。

## 能力生命周期
发现 → 来源/许可/版本核验 → 分类去重 → 方法提炼 → 中立能力定义 → 原生适配 → 隔离测试 → 真实任务测试 → 读回/失败验证 → 用户或授权 Agent 验收 → 能力资格确认 → 生成知识候选 → AAOS 正式审核/接收。

必须分别记录：Discovered、Reviewed、Adapted、Installed、Loaded/Connected、Tested、Qualified、Accepted、Knowledge Candidate、Ingested/Verified in AAOS。状态不能合并成一个“完成”。

## 模型策略
支持本地、云端和混合模型，不绑定单一 Provider。按视觉能力、中文理解、审美基准表现、工具调用可靠性、隐私、成本、延迟和可用性路由。
- 本地模型用于其能力覆盖的隐私敏感、高频、低成本和结构化任务；多模态能力须实测。
- 云端模型用于复杂多图分析、困难审美推理和本地能力不足的任务；数据发送须经授权。
- 可本地预处理后仅将获准的最小必要数据交给云端；服务不可用时降级到本地或人工。
- 模型输出是候选判断，不自动成为事实或知识。
- “本地可运行”不等于“职业级审美合格”，必须使用基准样本和人工评审。

## 设计软件接入策略
按任务优先考虑：官方 API/SDK → 原生插件 → MCP → 脚本/CLI → 受控 UI 自动化。不是所有工具都必须走 MCP。
每个 Adapter 声明宿主/版本、支持操作、输入输出 Schema、权限、数据流、前置条件、超时/取消、读回、失败模式、恢复/回滚、许可证和安全限制。MCP 握手、HTTP 200、退出码或截图都不能替代真实任务验证。

## 与 WORK-LAB 的边界
WORK-LAB 拥有通用工作流、Work Unit、全局配置/策略、权限与预算、跨项目路由、执行协调、运行监测、维护/恢复和通用回执。
DESIGN-LAB 拥有视觉领域定义、审美方法、提示词能力、设计能力 Registry、专业评价标准及设计工具能力规范。
通过版本化 Schema/API/Manifest/Adapter/Receipt/Candidate 协作，不直接写对方私有数据库。简单视觉任务可以直接使用 DESIGN-LAB；跨软件、多步骤、需统一授权或恢复的任务可请求 WORK-LAB，不强制所有设计任务经过 WORK-LAB。

## 与 AAOS 的边界
AAOS 是正式知识、来源/证据治理、审核和长期学习的权威。DESIGN-LAB 可维护设计运行所需的 Registry、方法卡、能力定义、评测集和操作规则，但不能取代 AAOS 的正式知识真源。
知识候选至少包含：ID、标题/类型/摘要、来源与原始资产引用、版权/许可证、允许用途、隐私/脱敏状态、领域/审美/风格/任务、版本、方法内容、适用条件、反例/失败模式、测试样本、模型/工具版本、结果/局限、验收主体/时间/理由、哈希与撤回信息。
DESIGN-LAB 只提交候选并读取 AAOS 返回的接收/审核状态；不得绕过审核直接写入可信知识。能力验收不自动等于 AAOS 知识已验证。

## 界面方向
DESIGN-LAB 有自己的专业界面，但界面服务于能力而非画布：Brief/任务上下文、参考图输入与视觉分析、Prompt Builder/反推、审美规则/Method Cards/Visual DNA、能力库、Adapter/Tool Registry、真实调用结果、测试对比、人工验收、知识候选及 AAOS 接收状态。系统日志和异常放入系统区域。禁止虚构评分、数据或接入状态。

## 执行步骤
1. 记录仓库、分支、HEAD、dirty 状态、Authority、索引、任务账本、实现和测试证据；保护未提交改动。
2. 建立冲突矩阵，对旧定位逐项标记 KEEP / AMEND / DEPRECATE / REJECT / OWNER DECISION。
3. 只更新必要权威文档，明确定位、非目标、六大能力域、模型/工具策略、WORK-LAB 边界和 AAOS 知识回流；保留历史和替代关系。
4. 将新方向映射到现有 Schema、Registry、Adapter 和既有 W00—W17 等任务；复用原账本，不另建重复总账或擅自发明编号。
5. 产出技术可行性矩阵：本地/云端视觉能力、提示词反推、API/MCP/插件/脚本/UI 自动化、读回/恢复、AAOS 接收。
6. 优先规划一个最小真实闭环：视觉输入 → 分析/提示词 → 合格工具调用或可验证输出 → 用户/授权 Agent 验收 → 知识候选。
7. 按变更范围运行测试并交付精确 SHA、命令、退出码、产物和未完成项。只改文档不得声称功能已实现。

## 防漂移
不重命名仓库、不重写无关目录、不覆盖 dirty 文件、不清理用户资产、不修改 WORK-LAB/AAOS、不绑定单一模型/MCP/宿主、不以星数代替质量、不默认外传素材、不以 AI 自评代替人工接受、不凭 Agent 自述关闭任务。遇到不可逆操作、许可不明、数据外发、跨仓库写入或权威冲突时暂停并报告。
