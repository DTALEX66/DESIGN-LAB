## 1. 交付

### 1.1 待审 / 失败列表（包内 W03 动作项）

仪表盘新增两个面板，数据来自**真实任务读回**（`/api/projects/{id}/tasks`，最多 8 个项目并行）。

判定词表**不是自创的**，而是 `src/design_lab/runtime/job_store.py` 的 attempt 状态机：

| 归类 | 状态 | 依据 |
|---|---|---|
| **失败** | `FAILED` / `TIMED_OUT` / `CANCELLED` | `TERMINAL - {RECEIPTED}` |
| **待审（需人工处理）** | `OUTCOME_UNKNOWN` / `CANCEL_REQUESTED` / `RECONCILING` | 非终态且需人工对账 |
| 进行中 | `PENDING` / `RUNNING` | 不计入以上两者 |

> **关键诚实点：`OUTCOME_UNKNOWN` 是「结果未知」，不是失败。** 派遣失败的任务其结果按服务
> 定义就是未知的；把它算进「失败」等于替服务宣布一个它明确拒绝宣布的结论。所以它进「待审」。

### 1.2 读不到 ≠ 没有（三态）

`apiOrEmpty` 对不可达服务返回**空载荷**，若照此渲染就会把「没读到」显示成「0 个失败」——那是
假数字。因此这两个面板改用 `api()` 逐项目读回并记录每项目成败：

| 情况 | 面板显示 |
|---|---|
| 有项目读回成功 | `待审（N）` / `失败（N）`，并注明 `已读回 x/y 个项目` |
| 一个都没读回 | **「未读回」**，并说明"此处不显示 0，避免把「没读到」说成「没有」" |

### 1.3 真实「最近项目」

原来「最近项目」只是 `/projects` 的**前 6 条**（名不符实）。现在打开某项目详情时在本机
记录其 id（`localStorage`，**只存 id、不上传**），仪表盘按最近打开排序并标注「最近打开」；
无记录时退回服务顺序，并在页面明说用的是哪种顺序。

## 2. 词表**交叉核验**（驱动器内，4 项）

分类器的正确性没有靠"看起来对"：驱动器在起完服务后**导入 `job_store`**，用正则解析
`shell.ts` 里声明的三个集合，逐条比对：

| 检查 | 结果 |
|---|---|
| `FAILED_STATES == TERMINAL - {RECEIPTED}` | PASS |
| `OUTCOME_UNKNOWN` 在待审、**不在**失败 | PASS |
| 每个 `ALLOWED` 状态都被归类 | PASS |
| 没有**超出**服务词表的自创状态 | PASS |

这样 UI 无法在状态机演进后**悄悄漂移**——一旦 `job_store` 改词表，这条检查立刻失败。

## 4. 本轮关于产品的三个真实结论（都是实测得出，不是推测）

1. **服务对 `/workbench` 文档本身也要求鉴权**。未带令牌访问 `/workbench?dev=1` 得到的是
   **401 JSON 响应体**，整页没有应用——我原先以为 dev 离线缝可以直接这样进入，**是错的**。
   因此「读不到」这一支改用**拦截 `/api/projects/*/tasks`** 来精确制造，比依赖 dev 缝更准。
2. **服务令牌只存在内存里**（`workbench.ts: export let token = ''`，无 localStorage/sessionStorage）。
   所以**刷新后回到连接界面**，必须重连。本轮把这条**断言**下来，而不是绕过去：重连前
   `#route-view` 显示的是「请先在工作台连接本机设计服务」，即**刷新后不显示任何陈旧/伪造数据**。
   若要「刷新后仍是已连接」，那是把令牌持久化的**安全决策**，本轮**不擅自做**。
3. **登录表单只在 workbench 路由可见**（`login.hidden = showWorkbench ? connected : true`），
   所以重连前必须先切回该路由。

于是「刷新保留项目上下文」的**准确**含义是：路由/hash 上下文保留 + 本机最近项目记录保留；
**会话本身不保留**（需重连，且这是刻意设计）。

## 5. harness 自身的错误（已记录）

| 错误 | 假结果 | 修法 |
|---|---|---|
| 把 hash 设成**它已经是的值** | 不触发 `hashchange` → 视图不重渲染 → 面板仍显示上一阶段的「未读回」，误判 EMPTY 分支失败 | 先切走再切回（**同一陷阱第二轮出现**） |
| 无条件断言「控制台零错误」 | 把**故意** `route.abort()` 造成的失败请求当成缺陷 | 给控制台错误打阶段标签，只允许 abort 阶段（**同一陷阱第二轮出现**） |
| 假设 dev 缝可从服务进入 | 整页 401，找不到任何面板 | 见 §4.1，改用请求拦截 |
