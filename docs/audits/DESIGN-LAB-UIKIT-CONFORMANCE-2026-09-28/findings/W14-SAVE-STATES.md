## 1. 依据（包内原文，不是我发明的词表）

> `01_RESEARCH_AND_PRODUCT.md:103`：**表单保存有 dirty、saving、saved、conflict 状态，
> 离开未保存页有恢复策略。**

因此状态标签就用这四个词，并且**把冲突与失败分开**——冲突是**可恢复**的（从最新版本继续），
校验/传输失败不是同一回事：

| 状态 | 标签 | 主要标签类 |
|---|---|---|
| 未修改 | `未修改` | info |
| 未保存 | `未保存（dirty）` | info |
| 保存中 | `保存中（saving）` | info |
| 已保存 | `已保存（saved）` | ok |
| **冲突** | `冲突（conflict·可恢复）` | **warn** |
| 失败 | `失败` | bad |

## 2. 离开未保存页的恢复策略

- 输入即写入**本机草稿**（按 `项目 + 表单` 分键，`localStorage`；**只在本机，不上传**）
- 返回该页时**恢复草稿并明示**「已恢复上次未保存的草稿…」，同时状态仍是 `未保存（dirty）`
  ——**不会**被伪装成已保存的版本
- 「丢弃草稿」一键清除，并注明「未改动服务端任何状态」
- 保存**成功**即清除草稿；保存失败**保留**草稿（可恢复）

## 3. harness 抓到的我自己代码里的一个顺序 bug

我最初把 `clearDraft()` 放在 `await refresh()` **之后**。而 `refresh()` 会**重新渲染**面板、
重新读取草稿 → 于是**保存成功后**面板反而显示「已恢复上次未保存的草稿」，
正是状态词表要消除的那种混乱。已改为**先清草稿再刷新**（创建与修订两条路径都改）。
harness 里对应的断言是 `a successful save CLEARS the draft`。
