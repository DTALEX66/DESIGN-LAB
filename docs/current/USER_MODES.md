# USER_MODES — 用户模式

- 版本：`1.0`｜状态：`ACTIVE`｜SSOT 角色：用户契约

## 五类用户，不做五套产品

| 用户 | 进入方式 | 关键价值 | 人必须决定的节点 |
|---|---|---|---|
| 职业设计师 | 在宿主项目中选择 Domain Pack | 专业方法、质量检查、可编辑交付 | 方向、版式、风格与交付放行 |
| 创意总监/大师 | 建立 Brief、评审方向与方法卡 | 设计判断显性化、匿名方法研究、Jury | 审美标准和最终认可 |
| 品牌/电商/空间从业者 | 选择行业场景与生产规格 | 商业目标、视觉系统、预检 | 商业约束、预算、物料与生产决策 |
| 新手 | Guided Brief + 基础 Rubric | 从灵感到规范化方向的渐进引导 | 参考物授权、方向选择、学习确认 |
| Agent/开发者 | 调用 Schema/Adapter Contract | 受控执行、读回、证据与回滚 | 范围、授权和异常处理 |

## 五种工作模式（mode 契约）

| 模式 ID | 说明 |
|---|---|
| `guided` | 新手渐进引导：Guided Brief + 基础 Rubric |
| `copilot` | 职业设计师协作：在宿主中选择 Domain Pack，专业方法辅助 |
| `director` | 创意总监评审：建立 Brief、评审方向与方法卡、Jury |
| `method` | 方法研究：匿名方法卡、风格谱系、设计判断显性化 |
| `production` | 生产交付：预检、可编辑 Handoff、BOM、证据 |

五种模式共享同一套引擎（单一能力闭环），**不做五套产品**。

## 视觉闭环（11 步）

01 Brief → 02 Rights/Source → 03 Research/Reference DNA/Method → 04 2–3 Directions → 05 **人锁定方向** → 06 Design System → 07 Host/Tool Adapter 执行 → 08 **质量 Jury** + 确定性检查 → 09 **生产预检** → 10 **可编辑 Handoff + BOM + Provenance + 回滚** → 11 证据/基准/人审反馈

任何自动化不得跳过步骤 02、05、08、09、10 的授权/人工判断。
