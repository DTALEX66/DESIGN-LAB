## 结论与缺陷

界面满足 DL-KB-03 的可见结构：检索是第一视觉入口，结果行只有标题、一句话用途、适用目标、
修订号与状态；正文、来源、许可、内容哈希与修订历史在详情里；零结果只解释，不推荐相近条目。
DL-KB-06 的侧栏由 `ROUTE_VIEWS` 派生（截图采集比对 21 个按钮 == 21 条路由，`CAP_NAV_SET`），
右上角设置入口存在，侧栏四个分组标签为「设计辅助 / 知识与提示词库 / 我的方案 / 设置与诊断」，
没有 AAOS 入口或连接按钮。125%/150% 下用 Tab 可以到达「知识与提示词库」，150% 时侧栏实际
滚动 263px 把它带进视口，焦点环为 3px solid，页面无横向溢出。

复核中发现并修复了四个缺陷（均已进入提交，最终复核的是修复后字节）：

1. **三个写入口换行** — 1440 下「新增 / 导入 / 重建索引」被挤到第二行（`1a7b7a2b`）。
2. **零结果标题重复服务句子** — 屏上出现「没有命中的条目没有命中「…」的条目。」（`2ac55ce1`）。
3. **表单打开后无法退出** — 新增/导入表单只能写入成功才消失，改主意只能离开页面（`4ffa77b8`）；
   现在行动区有「取消」，真实点击后表单从 DOM 移除（`kb-visual.mjs` 断言 detached）。
4. **零结果时右侧仍挂上一次选中** — 0 条结果旁边是一整块真实详情，读起来像本次命中（`7f5e68d7`）；
   现在它会显示「右侧是上次选中的条目，不在本次检索结果里——它不是这次检索的命中。」
   并由 `apps/workbench/tests/appshell.mjs` ㉓ 断言。

## 测到的数字

- 中文短词（「分镜」「粒子」「品牌」）在 1,000 条真实 HTTP 语料上全部命中，策略为
  `SHORT_FALLBACK`；`panasonic` 走 `TRIGRAM`；零结果带服务解释。
- 检索 p95：单元层 24.7 ms（首发）/ 26.1 ms（本条日志为此后的 UTF-8 重跑），
  真实 HTTP 层 30.4 ms，预算 300 ms（各 30 次采样，1,000 条）。
- 空库/零结果文案：「当前没有条目」「没有符合条件的结果」，都给出下一步，没有编造示例条目。
- 分页：首屏 50 行，`加载更多（已显示 50 / 共 60）`，点击后 60 行且按钮消失。
- 三个宽度与两个配色的 UI 审计、溢出、对比度闸门全绿（见同目录日志）。
