# `tokens.css` — Color Recipe

The default color section emitted by `/design init` and updated by `/palette`. Three layers (scale → semantic alias → optional component-scoped). Light + dark co-emitted (constitution rule #6).

## Defaults shipped

The system ships these scales by default:

- One **neutral** scale (`--color-neutral-{50..950}`) — drives surfaces and foregrounds.
- One **brand** scale (`--color-brand-{50..950}`) — used for primary CTAs, links, focus.
- Four **state** scales: `--color-success-*`, `--color-warning-*`, `--color-danger-*`, `--color-info-*`.

Total: 6 scales × 11 steps = 66 scale tokens. Plus ~20 semantic aliases. Plus dark-mode overrides on aliases only.

The brand scale is the one `/palette` rewrites; the others are stable defaults that can be customized but rarely need to be.

## Why these defaults

- **Neutral L anchors:** 98 / 14 (light surface / dark fg). 11 steps with bell C-curve peaking around 500.
- **Brand mid at L≈58:** typical for a 4.5:1 floor against white at the right step. Verify per palette.
- **Success H≈145, warning H≈75, danger H≈25, info H≈230:** standard semantic hues. Customize if brand requires.
- **Surface elevated = pure white in light, neutral-900 in dark:** elevated surfaces should be brighter than the app surface in light mode and brighter (lighter) than the surface in dark mode.

## Writing into an existing project

`/palette` writes into `tokens.css`:

1. **Idempotent.** Detects existing `--color-brand-*` tokens; replaces only the brand scale unless asked to regenerate everything.
2. **Preserves comments and order** where possible.
3. **Asks before destructive change** to neutral or state scales (constitution-respecting; see spec §6.1).

## Tailwind integration

When Tailwind is present, wire colors through CSS vars:

```js
// tailwind.config.* — never hardcoded values
module.exports = {
  theme: {
    extend: {
      colors: {
        neutral: {
          50: 'var(--color-neutral-50)',
          // ...
          950: 'var(--color-neutral-950)',
        },
        brand: { /* same shape */ },
        fg: 'var(--color-fg)',
        'fg-muted': 'var(--color-fg-muted)',
        surface: 'var(--color-surface)',
        'surface-elevated': 'var(--color-surface-elevated)',
        border: 'var(--color-border)',
        ring: 'var(--color-ring)',
        success: 'var(--color-success)',
        warning: 'var(--color-warning)',
        danger:  'var(--color-danger)',
        info:    'var(--color-info)',
      },
    },
  },
};
```

Tailwind's `border-DEFAULT`, `ring-DEFAULT` shape is acceptable; choose to match team convention.

## TypeScript export (when `tsconfig.json` present)

```ts
// theme.ts — typed token export
export const tokens = {
  color: {
    fg: 'var(--color-fg)',
    surface: 'var(--color-surface)',
    brand: 'var(--color-brand)',
    // ...
  },
} as const;

export type ColorToken = keyof typeof tokens.color;
```

Components consume `tokens.color.brand`, never raw hexes.

## Dark-mode strategy in this recipe

This recipe uses **alias-redefinition** dark mode (Strategy A in `ramps.md`):

- Scale tokens are the same in both modes.
- Aliases switch which scale step they reference.
- Brand token shifts from `brand-600` (light) to `brand-400` (dark) — both render visibly on their respective surfaces.

If the project needs a separately-tuned dark scale (premium brand work), ship `--color-brand-light-*` and `--color-brand-dark-*` and switch aliases to the right scale per theme. Document the deviation.

## Component-scoped tokens (Layer 2) — when

Add Layer 2 only when a component needs ≥ 5 distinct color decisions and inline `var(--color-…)` becomes noisy:

```css
.button {
  --button-bg:           var(--color-brand);
  --button-bg-hover:     var(--color-brand-700);
  --button-bg-active:    var(--color-brand-800);
  --button-bg-disabled:  var(--color-brand-200);
  --button-fg:           oklch(100% 0 0);
  --button-fg-disabled:  var(--color-brand-500);
}
```

For most components, Layer 1 is sufficient.

## Verification before shipping a token diff

- [ ] All new scale steps follow the L curve (no kinks).
- [ ] All semantic aliases resolve to a scale step (no orphans).
- [ ] All aliases have a dark-mode override.
- [ ] `--color-fg` on `--color-surface` and `--color-surface-elevated` passes WCAG AA in both themes.
- [ ] `--color-ring` is ≥ 3:1 against every surface it can sit on.
- [ ] Status color aliases are tested under deuteranopia/protanopia simulation.
- [ ] `prefers-contrast: more` block authored.
- [ ] No raw hex in component CSS (run `design-system-keeper`'s checks).

If any item fails, fix at the appropriate layer and re-verify.
