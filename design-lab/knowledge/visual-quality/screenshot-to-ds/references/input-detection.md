# 输入检测规则

## 核心：读控件区域，不读整页

无论输入是 App 截图还是控件展示板，**分析单位是「单个控件区域」**，不是「整张页面」。

```
参考图
├── ❌ 页面背景 / 留白 / 装饰 → 跳过
├── ❌ 状态栏 / Home Indicator → 跳过（除非本身是分析目标）
└── ✅ 按钮、输入框、卡片、列表行、Tab、Chip… → 逐个读取
```

## 输入类型判定

| 类型 | 特征 | 处理方式 |
|------|------|----------|
| 控件展示板 | 多类控件平铺/分组展示、无完整页面结构 | **首选**：直接枚举各控件区域 |
| UI 设计稿 | 干净背景、控件或组件标注 | 划定控件区域，忽略画板背景 |
| App 截图 | 满屏 UI、有完整页面布局 | **只提取其中可见的控件实例**，忽略页面布局与背景 |
| 手机拍屏 | 可见手机边框、透视 | 先裁切屏幕，再划定控件区域 |
| 多屏拼贴 | 一张图含多个页面 | 每页分别枚举控件区域 |
| 无 UI | 风景、文档、纯 logo | **停止**，告知用户需重新提供 |

## 控件区域划定

满足以下特征即视为一个控件区域：

- 有明确边界（圆角矩形、pill、圆形等）
- 可归类为标准控件（见 component-checklist）
- 与页面背景有视觉分隔（颜色、阴影、边框）

**划定步骤：**

1. 扫描全图，列出所有可识别控件实例（允许多个同类控件，如 3 个不同颜色的 ListItem）。
2. 为每个实例标注：类别、变体、在图中的位置描述。
3. 非控件区域（背景、插画、icon 图形）记入「排除清单」，不采样。

## 界面存在性检查

满足以下任意 1 项即可继续（不要求完整页面）：

- 可见 1 个及以上标准 UI 控件
- 控件展示板 / 组件标注

以下情况**停止**：

- 纯背景、纯文字段落、无 UI 控件
- 仅有 icon 图形、无容器控件

## 平台推断

从**控件风格**推断，而非页面结构：

| 信号 | 平台 |
|------|------|
| 大圆角 pill、SF 风格字号 | iOS |
| Material FAB、Ripple 暗示 | Android |
| 鼠标 hover 态展示 | Web |

## 拍屏裁切

1. 识别屏幕四边，裁切后**再**划定控件区域。
2. 透视严重时标注质量限制，不强行校正。

## 输出到 analysis.md 的字段

```markdown
## 输入检测

- 输入类型：控件展示板 / App 截图 / 设计稿 / 手机拍屏
- 分析模式：逐控件区域（非整页）
- 平台：iOS / Android / Web / 未知
- 控件区域数：N
- 排除区域：背景、状态栏、icon 图形…
- 质量限制：无 / 拍屏透视 / 低分辨率

## 控件区域清单

| # | 类别 | 变体 | 位置描述 | 是否纳入提取 |
|---|------|------|----------|--------------|
| 1 | Button | primary pill | 左上方 | ✅ |
| 2 | 背景 | 渐变装饰 | 全图底 | ❌ 排除 |
```
